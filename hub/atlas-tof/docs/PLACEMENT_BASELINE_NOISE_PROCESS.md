# ToF 자세 — 설치 기준(베이스라인)·잡음 측정·다음 모델 (2026-10-17)

실기(Pi 4 + VL53L8CX×2, 사람 60 cm) 에서 "위치 재조정"이 너무 자주 나온 뒤에 정리한 절차다.
결론 먼저:

1. **"위치 재조정"은 프레임마다 새로 판단할 일이 아니다.** 설치 때 한 번 "지금 위치가 적당하다"를 확정하고(베이스라인),
   그 뒤로는 **베이스라인 대비 변화**로만 장치 이동을 잡는다. 사람의 자세는 그 기준 위에서 판정한다.
2. **잡음 크기는 재서 정한다.** 지그가 나오면 65 cm 벽만 보게 두고 60 s 를 기록해 칸별 표준편차·드롭률을 남기고,
   "이 정도는 노이즈" 문턱을 거기서 뽑는다. 시뮬 잡음 파라미터도 그 값으로 맞춘다.
3. **다음 UBAI 모델은 "좁힌 배치 범위 + 베이스라인 상대 입력"** 이다. 사용자 확정 범위: 센서 높이 0.05~0.25 m, 기울기 0~25°, 좌우 ±45°.
   나머지(거리 0.5~0.8 m, 책상, 체형, 반사율, 방)는 r9 와 같다. 사양은 §3, 설정 파일은 `ubai_next/ubai_c9_range_config.json`.

지금 실기 상태(10-17 21:00): 장치가 사람 위쪽 벽을 본다(원본 8×8 위 5줄 = 2.5~3.9 m 벽, 사람 60 cm 는 아래 3줄).
CAD/지그 전이라 각도가 고정되지 않은 탓이 크다. 이 문서의 절차는 지그가 생긴 뒤 하는 것이다.

## 1. 설치 기준(베이스라인) 절차 — "적당한 위치"를 한 번 확정한다

### 1-1. 왜
- 모델은 시뮬에서 "장치가 이상하게 놓인 장면"을 `misplaced` 로 배웠다. 실기에서 센서가 벽을 많이 보면 그 라벨이 계속 나온다.
- 하지만 제품에서 장치 위치는 설치 뒤 거의 안 바뀐다. 매 프레임 "위치가 이상한가"를 묻는 대신,
  **설치 때 한 번 확인 → 그 뒤엔 "설치 때와 달라졌는가"** 만 보면 된다. 그러면 오탐이 사라지고 사람 자세 판정이 그 기준 위에서 안정된다.

### 1-2. 설치 시퀀스 (앱/서비스에 넣을 것)
1. **빈 자리 캡처(배경)** — 사람이 자리를 비운 채 10 s. 센서별 8×8 중앙값 `B_s[r][c]`(mm) 와 유효마스크를 저장한다.
   - 저장 위치: `/mnt/rawdata/deskmate_tof/baseline.json` (센서별 `median_mm[64]`, `valid[64]`, `std_mm[64]`, `captured_at`, `jig_id`).
2. **적당한 위치 판정(한 번)** — 배경 캡처에서 아래를 만족하면 "적당", 아니면 사용자에게 재배치를 요청한다.
   - 벽/배경이 보이는 칸 비율: 위 3줄(row 0~2)의 유효 칸 중 거리 ≥ 1.2 m 인 칸이 ≥ 60 % (= 머리 뒤 공간이 열려 있음)
   - 책상면/근접 장애물: 거리 < 0.35 m 인 칸이 전체의 ≤ 10 % (지그 앞 노트북·컵 등으로 가리지 않음)
   - 두 센서 겹침: 두 센서의 가운데 4×4 중앙값 차이 ≤ 25 % (한쪽만 벽·한쪽만 근접이면 실패)
   - 위 값들은 지그 기준으로 다시 잰 뒤 고친다(§2 의 결과로).
3. **착석 확인(선택)** — 사용자가 앉으면 가운데 줄(row 2~5)에 0.45~0.9 m 칸이 ≥ 12개 생겨야 한다. 안 되면 "조금 더 가까이/의자를 낮추세요".
4. 이 시점의 베이스라인을 **확정**하고, 서비스는 이후 입력을 베이스라인과 함께 쓴다(§1-3).

### 1-3. 운영 중 "장치 이동" 판정 (misplaced 의 새 정의)
- 프레임마다 **배경 칸**(베이스라인에서 거리 ≥ 1.2 m 였던 칸 중 지금도 유효한 칸)의 거리 변화를 본다.
  사람은 배경 칸을 가려도 "더 가까워질" 뿐이다. 장치가 움직이면 배경 칸이 **다른 거리로 바뀐다**(벽이 멀어지거나 바닥이 보임).
- 규칙: 배경 칸 중 `|d − B| > max(80 mm, 4·σ_noise)` 인 칸이 2 s 이상 ≥ 50 % 이면 `device_moved` 후보 →
  10 s 유지되면 `misplaced` 확정 + 재설치 안내. 사람이 지나가는 1~2 s 변화는 걸러진다.
- 모델의 `misplaced` 출력은 **이 규칙과 AND** 로만 쓴다(둘 다 켜져야 표시). 다음 모델(§3)에선 입력에 베이스라인 차이를 넣어 모델이 직접 배운다.
- 서비스 구현 위치(제안): `source/hub-atlas-tof/src/device_posture.cpp` 의 센서별 상태에 `baseline` 과 `moved_frac`, `/api/state` 에 `device_moved`, `POST /api/baseline` (캡처·확정).

## 2. 잡음 측정 절차 — "이 정도는 노이즈" 문턱을 숫자로

### 2-1. 준비 (지그 완성 후)
- 지그에 장치 고정, 센서 광축이 **65 cm 앞 벽(또는 흰 보드)** 에 수직. 사람·물체 없음, 조명은 실사용과 같게(형광등/창가 2조건).
- 보드 서비스는 그대로(중계기 `:8772/raw` 가 켜져 있으면 된다).

### 2-2. 기록
```powershell
cd rpi4_tof_deploy_20261017\pc
python -I tof_noise.py --raw http://<Pi4>:8772 --seconds 60 --label wall65_fluorescent --out noise\
```
- 60 s × 5 Hz × 2 센서 ≈ 600 프레임. 결과: `noise/<label>_<시각>.json` + 콘솔 요약.
- 조건을 바꿔 반복: `wall65_window`(창가), `wall100`(1 m), `wall65_dark`. 최소 2조건.

### 2-3. 기록하는 값 (파일에 그대로 남음)
| 값 | 뜻 | 쓰는 곳 |
|---|---|---|
| `zone_std_mm[64]` | 칸별 거리 표준편차 | 잡음 문턱 `σ_noise`(= 전체 칸 중앙값), 시뮬 `sigma0_mm` |
| `zone_mean_mm[64]`, `zone_p05/p95` | 칸별 평균·분위 | 벽이 평면인지(가장자리 칸 왜곡), 캘리브레이션 오프셋 |
| `dropout_rate[64]`, `status_hist` | 칸이 비는 비율, 상태값 분포 | 시뮬 `dropout`, `signal_min/semi` 재조정, 서비스 유효마스크 기준 |
| `frame_jitter_ms`, `hz` | 프레임 간격 분포 | 10 Hz 모델이 5 Hz 입력을 재사용하는 비율 확인 |
| `drift_mm_per_min` | 1분 구간 평균의 변화 | 열 드리프트. 베이스라인 재캡처 주기 결정 |
| `sensor_delta_mm` | 두 센서 가운데 4×4 중앙값 차 | 두 센서 정렬·거리 오프셋 |

### 2-4. 문턱 정하기
- `σ_noise = median(zone_std_mm)` (65 cm 벽). 운영 문턱은 `4·σ_noise`, 최소 80 mm (§1-3).
- 드롭률이 칸별로 2 % 를 넘는 칸은 "약한 칸"으로 표시해 베이스라인 판정에서 뺀다.
- 결과를 이 문서 §2-5 표에 적고, 시뮬 `L8Params(sigma0_mm, sigma1_mm, dropout)` 를 **실측에 맞춘 값으로 바꿔** 다음 학습에 쓴다.

### 2-5. 측정 결과 (채울 것)

|---|---|---|---|---|---|---|
| | wall65_fluorescent | | | | | |
| | wall65_window | | | | | |

(10-17 지그 없이 돌린 예비 실행은 `pc/noise/dryrun_*.json`. 벽만 본 조건이 아니라 참고만.)

## 3. 다음 UBAI 모델 — 무엇을 학습시키나

### 3-1. 판단
| 후보 | 배치 | 실기에 맞나 |
|---|---|---|
| r9_lowlr (지금 기본) | 무작위(높이 3~30 cm, 기울기 0~25°, 좌우 틀어짐) | 장치를 아무 데나 두는 조건용. 지그 고정에선 `misplaced` 과잉 |
| a9_demo | 정면 호 고정 | 시연엔 좋지만 `misplaced` 를 못 내고(재현율 0.00) 지그와 각도가 다르면 성능 급락 |
| **c9_range (확정)** | **높이 0.05~0.25 m · 기울기 0~25° · 좌우 ±45°(총 90°)** + 범위 밖 10 % = misplaced | 사용자 확정(10-17). misplaced 가 "설치 범위를 벗어남"을 뜻하게 됨 |

**c9_range** 로 간다. 핵심 두 가지:
1. **배치 범위를 좁힌다(사용자 확정 10-17).** 센서 높이 0.05~0.25 m, 위쪽 기울기 0~25°(지금과 같음), 좌우(요) -45°~+45°(총 90°), 모두 균일 분포.
   사람 거리 0.5~0.8 m·책상 0.70~0.76 m·체형·반사율·방(벽 없음 30 %, clutter 4, rich)은 r9 그대로.
   범위 밖(높이 0~0.05 또는 0.25~0.35 m, 기울기 25~40° 또는 -10~0°; 요는 ±45° 안)을 10 % 섞고 그것만 `misplaced` 로 라벨한다. → "위치 재조정"이 **설치 범위를 벗어난 상태**를 뜻한다.
2. **입력에 베이스라인 차이를 넣는다.** 세션마다 사람 없는 배경 프레임 `B` 를 먼저 렌더해 세 번째 채널 `(B − d)/4000`(가려진 만큼 양수)을 준다.
   모델이 "배경 대비 무엇이 앞에 있나"를 직접 보므로 배치·방 차이에 둔감해진다. 실기에서는 §1 의 베이스라인을 그 채널로 넣는다.
   (입력 (2,8,8) → (3,8,8). 서비스 `device_posture.cpp` 의 입력 조립과 `posture_net.bin` 헤더 확인 필요. 1차 실행은 채널 추가 없이 1번만 적용해도 된다 — `ubai_next/ubai_c9_range_config.json` 의 `input_baseline_channel` 로 켜고 끈다.)

보조:
- 잡음 파라미터는 §2 실측으로 교체(그 전엔 시뮬 기본 `sigma0 3, sigma1 4, dropout 0.003`).
- 초기화는 r9_lowlr `ckpt_best.pt` 에서 이어서(fine-tune), lr 2e-4, 12 h. 처음부터 하면 24 h.
- 검증: 시뮬 range 48세션 + **실측 지시자세 세션**(`real` 목록, 지그 뒤 10-18~ 수집) 으로 macro-F1. 실측이 들어가야 점수가 의미 있다.
- 두 센서는 지금처럼 센서별 추론 → log-softmax 합. 센서 두 개의 상대 각(바깥 8°)은 지그 값으로 고정.

### 3-2. 시뮬(tof-sim v5)에 필요한 변경 — 76EHwan/tof-sim
- `placement: "range"` 모드 추가: 설정의 `range` 블록(height_m, tilt_deg, yaw_deg, person_dist_m 의 [min,max], misplaced_frac, misplaced_def)대로 균일 추출.
  범위 안 = 정상 라벨, 범위 밖(`misplaced_frac`) = `misplaced`. (기존 random 은 높이 0.03~0.30·기울기 0~25·요 범위 미확인이므로 random 의 높이를 0.05~0.25, 요를 ±45° 로 자르는 것이 가장 작은 변경.)
- `input_baseline_channel: true` 이면 세션 시작 전에 사람을 뺀 장면을 한 프레임 렌더해 `B` 로 저장하고 입력 3채널 생성. export 시 `model_card.input.channels` 에 기록.
- `l8_params` 를 설정 파일에서 덮어쓸 수 있게(실측 잡음 반영).
- 지그(CAD)가 확정돼도 학습 범위는 위 값을 유지한다. 지그 값은 §1 베이스라인 판정 문턱을 정할 때 쓴다.

### 3-3. 실행 (UBAI)
```sh
# tof-sim v5 에 §3-2 반영 뒤
python train.py --config ubai_c9_range_config.json        # 12 h fine-tune (init = r9_lowlr ckpt_best)
python export.py --run ubai_c9_range                      # posture_net.bin / golden.txt / onnx / model_card
python bench_deploy.py --runs ubai_c9_range ubai_r9_lowlr ubai_a9_demo --sessions range48 real_*   # 같은 세션으로 비교
```
시뮬 변경이 늦어지면 **중간 단계**로 `ubai_c9_arc_ft_config.json`(기존 `arc` 배치를 좌우 ±45° 로 맞춰 r9_lowlr 에서 fine-tune)을 먼저 돌려 지그 시연용으로 쓴다. arc 의 각도 범위가 설정으로 안 바뀌면 그 한 줄만 코드에서 고친다.
단 이 모델은 misplaced 를 거의 못 내므로 §1-3 규칙이 misplaced 를 맡는다.
