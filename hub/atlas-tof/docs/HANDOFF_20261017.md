## 20:20 자세 찍힘 (데스크톱 세션, hub 미교체)
- 방법: **노트북 중계** `pc/uart_relay_pc.py` — `ssh root@172.20.10.3 cat /dev/ttyAMA0` 로 ESP32 UART 원본을 끌어와
  COBS/CRC 를 풀고 TYPE 0x05 만 `UART\t{"type":5,...,"payload_hex":...}` 줄로 바꿔 172.20.10.3:9100 에 넣는다.
  실행: `python -I pc\uart_relay_pc.py --to 172.20.10.3:9100` (터미널에 켜 둬야 함. 끄면 센서 0개로 돌아감)
- 결과: /health online_sensors 2 (`tcp:9100#s0` 4.9 Hz, `#s1` 5.0 Hz), /api/state posture=misplaced conf 0.95
  (센서 0 은 13~85 cm 근접 물체, 센서 1 은 2.1~3 m 벽 → 앞에 사람 없음. 실제 착석 시험은 아직)
- 알게 된 것 두 가지(hub 중계기 만들 때 그대로 적용할 것):
  1. **펌웨어 0x05 payload 는 grid 배치**(grid_w,grid_h,sensor,sensors,frame_id,mask,flags(b0 flip_rows,b1 flip_cols),res + i16 dist + u8 st)
     인데 자세 서비스 파서는 **v1 배치**(version=1,sensor_id,flags(b0 valid,b1 has_status,b2 flip_rows,b3 flip_cols),w,h,res,frame_seq u16 + u16 dist + u8 st)만 읽는다.
     그대로 넘기면 version!=1 로 버려진다. 변환이 필요(uart_relay_pc.py `to_service_payload`). 펌웨어 flags=0x02 → v1 0x0b.
  2. 서비스의 JSON 파서는 `"payload_hex":"…"` 처럼 **콜론 뒤 공백이 없어야** 읽는다(`"payload_hex": "…"` 는 lines 만 늘고 frames 0).
- 보드 env 는 TOFPOSTURE_PORTS=tcp:9100 (CLI 세션 설정 그대로), FLIP_ROWS/COLS=0 강제(10-15 env). 펌웨어는 flip_cols 필요라고 보내므로
  방향 확인 뒤 FLIP_COLS 를 비우거나 1 로 맞출 것. 보드의 hub·그 밖 파일은 안 건드림. hub 중계 바이너리는 /tmp/deskmate_hub_service.relay 그대로.
