# ToF 벽 잡음 측정 — 하드웨어를 가진 사람(과 그 사람의 Claude)용 절차 (2026-10-24)

장치를 벽에 비춰 두고 일정 시간 동안 VL53L8CX 두 개의 8×8 거리값이 얼마나 흔들리는지 잰다. 이어서 사람이 가만히 앉아 있을 때와 비교한다.
도구는 `hub/atlas-tof/pc/tof_wall_noise.py` 한 파일이다(표준 라이브러리만 쓰고 Python 3.8+). 이 문서가 그 순서다.
**이 문서를 받은 Claude 는 §1 부터 읽는다.** 숫자를 해석해 고치는 일(§10)은 결과를 돌려받은 쪽이 한다.

## 1. 이 문서를 받은 Claude 에게

**할 일 순서**

1. 코드를 받고 `selftest` 가 통과하는지 본다(§4-1).
2. Pi 5 주소를 알아낸다(§3-1).
3. `aim --pi5 <PI5> --distance-cm 45` 로 연결과 프레임 수신을 확인한다(§3-2). 이 명령은 Claude 셸에서 돌려도 된다(30초 안쪽).
4. 사람에게 §5 의 `session` 명령을 **사람의 PowerShell 창에서** 실행해 달라고 한다.
   - 소리·Enter 가 필요하고 25분쯤 걸리므로 Claude 셸에서는 돌리지 않는다.
   - 그동안 Claude 는 기다린다. 사람이 끝났다고 하면 다음으로 간다.
5. 세션 폴더의 `SESSION.md` 를 읽고, zip 을 만들고, 돌려보낼 내용을 정리한다(§7).

사람이 터미널을 쓰기 어렵다면 Claude 가 단계마다 `record` 를 직접 돌린다(§6). 이때는 도구 timeout 에 주의한다.

**하지 말 것**

- 보드 설정을 바꾸지 않는다: `tofposture.env`, 모델 파일, 펌웨어(ESP32 다시 굽기) 전부. 재시작은 §9 표에 적힌 경우에만, 사람에게 확인받고 한다.
- ESP32 의 USB 시리얼(`/dev/ttyUSB0`)을 중계기 말고 다른 프로세스로 열지 않는다. 두 프로세스가 읽으면 프레임이 쪼개진다.
- 측정 원본(`noise_runs\`)과 zip 을 git 에 커밋하지 않는다. 팀 규칙이 데이터셋 커밋 금지이고, `noise_runs/` 는 `.gitignore` 에 들어 있다.
- `main` 에 push 하지 않는다.
- 카메라·마이크는 쓰지 않는다.
- 조명·벽 재질·지그 기울기·기기→턱 거리 같은 메모는 **지어내지 않는다.** 사람에게 묻는다(`session` 은 시작할 때 직접 묻는다).
- 막히면 같이 있는 사람에게 묻는다. 사람이 모르는 것(보드 설정 이력 등)은 이 문서를 준 사람에게 물어 달라고 한다.

## 2. 왜 재는가

- Pi 4 자세 서비스(`deskmate_tofposture`, GRU 모델)는 실기에서 자세를 대체로 맞히지만 **`drowsy`(졸음)가 너무 자주 뜬다.**
- 모델은 시뮬(tof-sim v5)로 배웠다. 시뮬의 센서 잡음은 **프레임마다 독립인 가우시안**이다.
  - 크기: `σ = √(3² + (4/√s)²) mm`(s = 신호 ≈ 반사율/거리²). `tofsim/l8.py` 의 `L8Params(sigma0_mm=3, sigma1_mm=4, dropout=0.003)`.
  - 60 cm 흰 벽이면 **약 4.1 mm** 다.
  - 시뮬 사람도 실제 사람보다 덜 흔들린다.
- 그래서 두 가지를 숫자로 가른다.
  1. **센서 잡음**: 아무것도 안 움직이는 벽을 볼 때 칸마다 거리값이 얼마나, 어떤 속도로 흔들리나. 시뮬보다 얼마나 큰가.
     잡음이 끄덕임 대역(0.2~1 Hz)에 걸쳐 있으면 모델이 "고개가 까딱인다"로 읽을 수 있다.
  2. **사람 몸 흔들림**: 사람이 가만히 앉았을 때의 흔들림이 벽 잡음보다 큰가.
- 결과로 정하는 것:
  - 시뮬 잡음 값(`L8Params`)을 실측으로 바꿀지
  - 입력 전에 필터를 넣을지(ESP32 평균 / Pi 4 의 median·EMA)
  - 시뮬 사람에게 미세 흔들림을 넣을지

### 2-1. 얼마나 길게 재야 하나 — 3시간이 필요한가

**잡음을 재는 데는 조건마다 5분이면 충분하다.** 벽을 3시간 비추는 것은 필요 없다.

- 5분이면 칸마다 프레임이 약 1,500개다.
  - 흰 잡음이면 σ 추정 오차는 약 ±2 %, 느린 잡음(1 프레임 자기상관 0.8)이라도 약 ±6 %.
  - 끄덕임 대역(0.2~1 Hz)은 5분 안에 60~300 주기가 들어가 값이 안정된다.
- 벽 앞에서 시간을 늘려 더 알 수 있는 것은 온도 드리프트 하나뿐이다. 그건 아래 "워밍업" 녹화 한 번으로 본다.
- 긴 녹화가 값진 곳은 **실제 작업** 쪽이다. 깨어 있는데 drowsy 가 한 시간에 몇 번 뜨는지, 언제 뜨는지는 길게 볼수록 정확하다.
  여유가 있으면 세션 뒤에 아래를 더한다(§6-3).

| 선택 녹화 | 길이 | 용량 | 무엇을 알 수 있나 |
|---|---|---|---|
| 워밍업 `warm60` | ESP32 를 막 켠 직후부터 벽 60 cm 30분 | 약 14 MB | 켠 뒤 몇 분 지나야 거리가 안정되는지(드리프트 곡선) |
| 긴 작업 `worklong` | 평소 작업 1~3시간 | 1시간 약 28 MB, 3시간 약 83 MB | 깨어 있는 동안 drowsy 오탐이 시간당 몇 번인지. 실제로 졸렸던 때는 사람이 시각을 적어 둔다 |

## 3. 구성과 접속

```
ESP32(esp32dev_usb, VL53L8CX ×2) ─USB─► Pi 4 ─ uart_relay_board ─tcp:9100─► deskmate_tofposture :8771 (/api/state 자세)
   A = 장치를 마주 보고 왼쪽 모듈            └─ :8772/raw (센서별 마지막 8×8 거리 mm·상태값)
   B = 오른쪽 모듈
Pi 4 eth0 172.16.34.199 ═ 랜선 ═ Pi 5 eth0 172.16.34.198 ··· Pi 5 wlan0 ─ 휴대폰 핫스팟 ─ PC (이 도구)
                                  Pi 5 = 7" 화면(자세 표시 앱)
```

- Pi 4 는 Wi-Fi 에 안 붙고 Pi 5 뒤 랜선에만 있다. PC 는 **Pi 5 를 거쳐(ssh -J)** Pi 4 에 간다.
- 보드 root 는 빈 비밀번호다. dropbear 가 묻지 않고 들인다.
- 보드는 **ping 에 답하지 않는다.** 살아 있는지는 22 번 포트로 본다.

### 3-1. Pi 5 주소 찾기

PC 를 Pi 5 와 같은 휴대폰 핫스팟에 붙인다. VPN 이나 Cloudflare WARP 는 끈다. 그다음 아래 중 하나로 주소를 찾는다.

1. 사람이 전에 쓰던 주소를 알면 그것부터 시도한다. 핫스팟마다 주소가 바뀔 수 있다.
2. 저장소 루트에서 스크립트를 돌린다:
   ```powershell
   powershell -ExecutionPolicy Bypass -File tools\find-boards.ps1
   ```
   - Pi 5 wlan0 MAC `88-a2-9e-3c-cc-b4` 로 찾아 준다.
   - **"Pi 4 못 찾음"은 정상**이다(Pi 4 는 Wi-Fi 에 없다).
   - Wi-Fi 어댑터 이름이 `Wi-Fi` 가 아니면 `-Interface "Wi-Fi 2"` 처럼 준다.
3. 이웃 표에서 바로 본다(그 전에 2번을 한 번 돌렸거나 핫스팟 대역에 접속을 시도한 적이 있어야 나온다):
   ```powershell
   Get-NetNeighbor -AddressFamily IPv4 | Where-Object LinkLayerAddress -eq '88-A2-9E-3C-CC-B4'
   Test-NetConnection <PI5> -Port 22        # TcpTestSucceeded : True 면 살아 있다
   ```

아래에서 `<PI5>` = 그 주소(예: 172.20.10.10).

### 3-2. 연결 확인 — `--pi5` 가 터널을 알아서 연다

```powershell
cd hub\atlas-tof\pc
python -I tof_wall_noise.py aim --pi5 <PI5> --distance-cm 45
```

- `--pi5` 를 주면 스크립트가 `ssh -J` 터널(PC → Pi 5 → Pi 4 의 :8772·:8771)을 직접 열고, 끝나면 닫는다. 창을 따로 열어 둘 필요가 없다.
- 처음 보는 보드 호스트 키는 스스로 받는다(`accept-new`). "키가 바뀌었다" 경고가 나오면 멈추고 사람에게 보여 준다. known_hosts 정리는 사람이 판단한다.
- 성공하면 `터널 열림: …` 다음에 센서별 8×8 격자와 한 줄 판정이 나온다. **헤더의 `프레임 N (x/s)` 가 3초에 약 15(≈5/s)** 면 정상이다.
- `python` 이 Microsoft Store 안내만 띄우면 `py -3 -I tof_wall_noise.py …` 로 바꿔 쓴다.

**사람이 직접 터널을 열 때**(뷰어도 같이 볼 때)는 창 하나에서 아래를 실행해 열어 두고, 명령에서 `--pi5` 를 빼면 된다(스크립트가 127.0.0.1:8772/8771 을 쓴다):

```powershell
ssh -N -o ServerAliveInterval=15 -L 8771:127.0.0.1:8771 -L 8772:127.0.0.1:8772 -J root@<PI5> root@172.16.34.199
```

### 3-3. 보드 상태 보기 (읽기만, 필요할 때만)

`aim --pi5` 가 한 번 성공하면 두 보드의 호스트 키가 저장돼 있어서 아래 한 줄이 바로 된다:

```powershell
ssh -o BatchMode=yes -J root@<PI5> root@172.16.34.199 "sh /mnt/rawdata/deskmate_tof/relay.sh status; sh /mnt/rawdata/deskmate_tof/status.sh"
```

- 중계기 로그는 10초마다 한 줄씩 쌓인다. 10초 뒤 한 번 더 돌려 `type5=` 숫자가 늘었으면 정상이다.
- `(idle)` 이 붙어 있으면 ESP32 에서 바이트가 안 온다는 뜻이다(§9).

### 4-2. 준비물·조건

| 항목 | 규칙 |

| 보드 | 아무것도 안 바꾼다. 자세 서비스는 켠 채로 둔다. 벽만 볼 때, 가만히 앉았을 때 모델이 뭐라고 하는지도 같이 남긴다 |

## 5. 안내 진행 — 사람이 PowerShell 창에서 (권장)

```powershell
cd hub\atlas-tof\pc
python -I tof_wall_noise.py session --pi5 <PI5>
```

시작하면 메모 네 가지를 묻는다:
- 조명
- 벽 재질·색
- 지그 기울기(대략)
- 평소 앉을 때 기기→턱 거리

모르면 Enter 로 넘어간다. 그다음 단계마다 이렇게 돈다:

1. 단계 안내 문구가 나오고, 3초 조준 격자가 찍힌다. 설정 거리 대비 가운데 거리와 프레임 수가 보인다.
2. **띵띵**(준비 알림) — 20초마다 다시 울린다.
3. 거리를 바꾸고 격자를 확인한 뒤 키를 누른다:
   - **Enter**: 녹화 시작
   - `r` + Enter: 격자 다시 보기
   - `s` + Enter: 이 단계 건너뛰기
   - `q` + Enter: 여기서 끝내고 정리
4. 5초 카운트다운(**틱** 소리, "시야에서 물러나세요" / "앉은 자세로 준비하세요") → **삐—** 하고 녹화가 시작된다. 15초마다 진행 줄이 찍힌다.
5. 끝나면 바로 분석해 센서별 σ·놓침 %·끄덕임 대역(사람 단계는 drowsy 비율)을 보여 주고 **띠리링**(완료) 한다.
   - 문제가 있으면 **뚜—** 소리와 함께 이유가 나온다(프레임 10 % 넘게 놓침, 벽 σ 60 mm 초과, 센서 멈춤).
   - 이때 Enter 를 누르면 그 녹화를 `_bad\` 로 옮기고 다시 녹화한다. `n` 을 누르면 그대로 쓴다.
6. 세 단계가 끝나면 거리별 맞춤을 하고 `SESSION.md` 를 쓴 뒤 **띠리리링**(끝) 한다. `SESSION.md` 끝에 사람 단계를 이어서 하는 명령이 적혀 나온다.

| 단계 | 시간 | 장치 | 사람 |
|---|---|---|---|
| `wall45` | 5분 | 벽 앞, 센서 커버~벽 45 cm | 시야 밖 |
| `wall50` | 5분 | 벽 50 cm | 시야 밖 |
| `wall60` | 5분 | 벽 60 cm | 시야 밖 |

- **중간에 끊겼으면**(창을 닫음·PC 잠듦 등) 같은 폴더에 남은 단계만 이어서 녹화한다. 이미 끝난 단계는 `session.json` 에 남아 있다.
  ```powershell
  python -I tof_wall_noise.py session --pi5 <PI5> --session-dir noise_runs\session_<시각> --steps wall60
  ```
- 녹화 중 Ctrl+C 를 누르면 그때까지로 분석해 그 단계를 끝낸다(문제가 있으면 다시 녹화할지 묻는다). Enter 를 기다릴 때 Ctrl+C 는 `q` 와 같다.
- 소리를 끄려면 `--no-beep` 를 준다.

### 5-1. 나중에 — 사람 단계 (지금은 안 함)

벽 세션과 **같은 폴더**에 이어서 하면 그 폴더의 `wall60` 을 기준으로 벽 vs 사람 비교까지 해 준다.

```powershell
python -I tof_wall_noise.py session --pi5 <PI5> --session-dir noise_runs\session_<시각> --steps empty,still,work
```

| 단계 | 시간 | 장치 | 사람 |
|---|---|---|---|
| `empty` | 1분 | **평소 쓰는 자리**(책상 위, 의자 쪽)로 옮긴다. 이제부터 끝까지 장치를 움직이지 않는다 | 의자는 평소 위치, 사람은 시야 밖 |
| `still` | 3분 | 그대로 | 평소 자리에 앉아 바른 자세로 최대한 가만히. 눈 뜨고 화면을 본다. 손은 무릎이나 책상 위(타이핑 안 함). 졸지 않는다 |
| `work` | 5분 | 그대로 | 평소처럼 작업(타이핑·화면 보기). 졸지 않는다 |

- `empty`(빈 자리)는 "사람 칸"을 고르는 기준이다. 빈 자리보다 10 cm 넘게 가까워진 칸만 사람으로 보고, 책상·의자 등받이는 뺀다.
- 벽과 사람 단계를 처음부터 한 번에 하려면 `session --pi5 <PI5> --with-person`.

## 6. Claude 가 단계별로 돌릴 때 (사람이 터미널을 못 쓸 때)

### 6-1. 녹화 한 번

```powershell
python -I tof_wall_noise.py record --pi5 <PI5> --label wall45 --distance-cm 45 --seconds 300 --light "<사람에게 물은 조명>" --note "<벽 재질, 지그 기울기>"
```

- **도구 timeout:** Bash/PowerShell 도구의 기본 timeout(120 s)이면 녹화 도중 프로세스가 죽는다.
  timeout 을 `(녹화 초 + 120) × 1000` ms 이상으로 준다. 300초면 `timeout: 420000`, 한도(600000)를 넘는 긴 녹화는 `run_in_background`.
  죽었으면 남은 폴더를 `analyze noise_runs\<폴더>` 로 복구 분석한다.
- 부르기 전에 사람에게 거리를 맞추고 시야에서 물러나 달라고 말한다. 시작 전에 5초 카운트다운이 있다(`--delay`).
- 끝 코드:
  - `0` = OK
  - `1` = 녹화 못 함(연결·멈춤, 이유가 찍힌다)
  - `3` = 녹화는 됐지만 다시 할 만한 문제(이유가 찍힌다). 그 폴더는 `noise_runs\_bad\` 로 옮기고 다시 녹화한다
- `--label` 은 `wall45`, `wall50`, `wall60`(사람 단계는 나중에 `empty`, `still`, `work`).
  - `wall*` 이면 벽, `empty` 면 빈 자리, 나머지는 사람으로 본다. 다르면 `--kind` 로 준다.
  - 사람 단계는 `--distance-cm` 를 비운다. 사람 단계 전에는 `aim --pi5 <PI5> --person` 으로 격자에 사람이 가운데 오는지 본다.
  - `--seconds`: `empty` 60, `still` 180, `work` 300.

### 6-2. 맞춤·비교

폴더 이름은 **끝까지** 쓴다. 와일드카드가 두 개 이상에 맞으면 `compare` 는 멈춘다.

```powershell
python -I tof_wall_noise.py fit noise_runs\wall45_<시각> noise_runs\wall50_<시각> noise_runs\wall60_<시각>
python -I tof_wall_noise.py compare --wall noise_runs\wall60_<시각> --still noise_runs\still_<시각> --empty noise_runs\empty_<시각>
python -I tof_wall_noise.py compare --wall noise_runs\wall60_<시각> --still noise_runs\work_<시각> --empty noise_runs\empty_<시각>
```

- `fit` 은 맞춤에 쓴 녹화와 뺀 녹화(σ 60 mm 초과·놓침 10 % 초과)를 첫 줄에 찍는다. 뺀 것이 있으면 사람에게 알린다.
- 버린 녹화는 `fit` 에 넘기지 않는다. `noise_runs\_bad\` 로 옮겨 두면 헷갈리지 않는다.

### 6-3. 선택 녹화 (§2-1)

```powershell
python -I tof_wall_noise.py record --pi5 <PI5> --label warm60 --kind wall --distance-cm 60 --seconds 1800 --note "ESP32 막 켬, <벽·지그>"
python -I tof_wall_noise.py record --pi5 <PI5> --label worklong --kind person --seconds 10800 --note "<기기→턱>, 졸렸던 시각: 사람이 따로 적음"
python -I tof_wall_noise.py record --pi5 <PI5> --label dark60 --kind wall --distance-cm 60 --seconds 300 --light "소등"
```

- 30분·3시간은 Claude 도구 timeout 한도를 넘는다. 사람의 PowerShell 창에서 돌리거나 `run_in_background` 로 띄운다.
- 3시간 녹화의 분석은 1분 남짓 걸린다.

## 8. 시간·용량

실측 기준(10-19 실기 녹화 한 줄 576 B, `/api/state` 한 줄 약 1.9 KB):

- `frames.jsonl`: 센서 2개 × 5 Hz = 10줄/s → **0.35 MB/분**
- `state.jsonl`: 1줄/s → **0.11 MB/분**
- 합계 **약 0.46 MB/분**. 녹화마다 분석 파일(report·summary) 약 0.06 MB 가 더 붙는다.
- zip 하면 약 1/4 로 준다.

| 단계 | 녹화 | 용량 |
|---|---|---|
| **지금: 벽 45 / 50 / 60 cm** | **5분 × 3 = 15분, 진행 약 25분** | **3 × 2.4 MB ≈ 7.2 MB (zip 약 2 MB)** |
| 나중: 빈 자리 | 1분 | 0.5 MB |
| 나중: 가만히 앉기 | 3분 | 1.4 MB |
| 나중: 평소 작업 | 5분 | 2.4 MB |
| (벽 + 사람 단계 모두) | 녹화 24분, 진행 약 40분 | 약 11.5 MB (zip 약 3 MB) |
| (선택) 워밍업 30분 | 30분 | 약 14 MB |
| (선택) 긴 작업 1 / 3시간 | 1 / 3시간 | 약 28 / 83 MB (zip 약 7 / 21 MB) |

- 걸리는 시간(사람 기준, 벽만): 준비·연결 10~15분, 세션 약 25분, 정리 5분 → **약 45분**.
- 세션 25분 = 녹화 15분 + 단계마다 거리 바꾸기·조준·카운트다운·분석 2~3분.
- 분석 시간은 5분 녹화가 2~3초, 3시간 녹화가 1분 남짓이다.

## 9. 안 될 때

| 증상(찍히는 말) | 볼 것 |
|---|---|
| `Pi 5(…) ssh 실패: … Connection timed out / refused` | Pi 5 주소(§3-1), 같은 핫스팟인지, VPN 끄기 |
| `Pi 4 터널 실패(Pi 5 … 거쳐 …)` | Pi 5 에서 `cat /sys/class/net/eth0/carrier` 가 1 인지(0 이면 랜선 다시 꽂기). Pi 4 주소: `ssh root@<PI5> "ip neigh show dev eth0"` → `--pi4 <주소>` |
| `REMOTE HOST IDENTIFICATION HAS CHANGED` 가 섞여 나옴 | 멈추고 사람에게 보여 준다(known_hosts 정리는 사람 판단) |
| aim: `프레임 없음(요청 실패 N) — 터널·중계기 확인` / record: `녹화 못 함: 중계기 … 에 못 붙음` | 중계기가 안 돈다 → §3-3 상태 보기 → 아래 재기동 |
| `중계기는 응답하지만 ToF 격자가 없다(have=false)` | ESP32 USB-C ↔ Pi 4 USB-A 케이블, ESP32 부팅 30 s 기다리기 |
| aim: `→ 프레임이 3 s 에 N개뿐` / record: `프레임 번호가 안 는다` | ESP32 가 멈췄거나 USB 가 빠졌다. 중계기는 마지막 프레임을 계속 준다. 케이블을 다시 꽂고 30 s 뒤 다시 |
| 녹화 중 `! 센서 N: 프레임이 3 s 째 안 들어온다` | 위와 같음. 다시 들어오면 `다시 들어온다` 가 찍힌다. 끝난 뒤 놓침 % 가 크면 다시 녹화 |
| `프레임 N % 놓침` (5 % 넘음, 10 % 넘으면 다시 녹화) | 뷰어 탭·Pi 5 프리뷰 탭 끄기. `meta.json` 의 `poll_latency_ms.median` 이 200 넘으면 핫스팟이 느리다 → PC 를 Pi 5 가까이, `--pollers 5`(session·record 둘 다 된다) |
| 센서가 하나만 보임(`센서 1개만 보인다`) | 그대로 측정하고 메모에 적는다(A 배선 이력) |
| aim 격자에 `*`(15 cm 이내) 칸 | 렌즈 커버 앞 이물질·실·보호 필름 |
| `σ 가 NN mm — 센서 잡음이라기엔 너무 크다` | 녹화 중 시야 안에서 뭔가 움직였다 → 다시 녹화 |
| `드리프트 … mm/분` | ESP32 켠 지 얼마 안 됐다 → 5분 더 두고 다시 |
| `자세 서비스 응답 없음` | 거리만 녹화된다(그래도 된다). 서비스 상태는 `status.sh` |
| **중계기만 꺼짐**(`relay.sh status` 에 실행 중이 아님) | 사람에게 확인받고 `ssh -o BatchMode=yes -J root@<PI5> root@172.16.34.199 "sh /mnt/rawdata/deskmate_tof/relay.sh"` |
| **둘 다 꺼짐**(보드 재부팅 뒤) | 사람에게 확인받고 `ssh -o BatchMode=yes -J root@<PI5> root@172.16.34.199 "sh /mnt/rawdata/deskmate_tof/start.sh; sh /mnt/rawdata/deskmate_tof/relay.sh"` (`;` 라서 서비스가 실패해도 중계기는 뜬다) |
| 소리가 안 남 | PC 음소거·볼륨. 소리 없이도 화면 안내대로 하면 된다 |
| 한글이 깨져 보임 | 콘솔: `chcp 65001` 뒤 다시. 파일 읽기: `Get-Content -Encoding UTF8` |

## 10. 결과 읽는 법 (결과를 받은 쪽용, 참고)

`summary.md` 의 지표는 칸마다 시간축으로 계산하고, 센서 요약은 유효율 90 % 이상 칸의 중앙값이다:

| 지표 | 뜻 | 흰 잡음이면 |
|---|---|---|
| σ (`std_mm`) | 칸 거리값 표준편차 | 시뮬 60 cm 흰 벽 ≈ 4.1 mm |
| 프레임차 σ (`diff_std_mm`) | 연속 두 프레임 차 RMS/√2 — 프레임마다 새로 생기는 성분 | ≈ σ |
| 1 s 평균 σ (`slow_ratio`) | 1 s 이동평균의 흔들림, 흰 잡음 기대값 대비 배수 | ≈ 1 |
| 끄덕임 대역 (`nod_rms_mm`, `nod_ratio`) | (1 s 평균 − 5 s 평균) RMS ≈ 0.2~1 Hz | 배수 ≈ 1 |
| `lag1_r` | 1 프레임 자기상관 | ≈ 0 |
| 공통 (`common_ratio`) | 모든 칸이 같이 움직이는 성분, 칸끼리 독립일 때 대비 | ≈ 1 |
| 놓침 % (`lost_pct`) | PC 가 못 받은 프레임(seq 갭). 5 % 넘으면 끄덕임 대역이 낮게 나온다 | 0 |
| 깜빡임 칸 | 유효↔무효가 분당 1번 넘게 바뀌는 칸(모델 입력 채널 1 이 깜빡임) | 0 |
| 필터 표 | 칸마다 온라인 적용(mean3·median3·median5·ema0.5·ema0.3) 뒤 σ·끄덕임 대역·지연. 앞 10분 표본 기준 | mean3 ≈ σ/√3 |

판단 → 다음 조치 후보:

| 관찰 | 뜻 | 후보 |
|---|---|---|
| 벽 σ 가 시뮬의 몇 배 이상 | 모델이 학습 때 못 본 크기의 흔들림 | `fit` 의 `L8Params` 로 시뮬 교체 후 재학습, 또는 입력 전 필터 |
| `slow_ratio`≈1, 프레임차 σ≈σ | 흰 잡음이라 짧은 평균으로 준다 | ESP32 가 15 Hz 표본 3개를 평균해 5 Hz 로 보낸다(√3 감소, 지연 약 133 ms). 지금 펌웨어는 15 Hz 로 재고 3개 중 1개만 보낸다(`main.cpp` `kTofGridPeriodMs`). 또는 Pi 4 중계기·서비스에서 median3·EMA |
| `slow_ratio`≥1.5, `lag1_r`>0.3 | 느린 잡음이라 짧은 필터로 덜 준다 | 시뮬 잡음에 AR(1)(ρ = `fit` 의 lag1) 추가, 센서 적분 시간↑(autonomous 모드) 검토 |
| 끄덕임 대역 배수≥1.5 (벽) | 센서 자체가 끄덕임 대역에 성분을 낸다 | 위 둘 + drowsy 판정에 지속 시간 조건 |
| 깜빡임 칸 여럿 | 유효 마스크가 흔들린다 | 유효 판정 히스테리시스(n 프레임 연속), 시뮬 dropout 상향 |
| `common_ratio`≥3 | 프레임 전체 오프셋이 흔들린다 | 온도·전원·타이밍, 센서별 오프셋 보정 |
| 벽 녹화에서도 drowsy 가 나옴 | 잡음만으로 모델이 졸음을 낸다 | 필터 우선 |
| compare "사람 몸의 느린 흔들림이 센서 잡음보다 크다" | 실제 사람이 시뮬보다 흔들린다 | 시뮬 사람에게 미세 흔들림(0.2~1 Hz, 수 mm~수 cm) 추가, drowsy 지속 시간 조건 |
| compare "센서 잡음이 주원인" | 흔들림 대부분이 잡음 | 필터·펌웨어 평균 |
| still·work 에서 drowsy 비율 | 깨어 있는데 졸음이 뜨는 실측 비율. 위 원인과 함께 본다 | — |

- **데이터 형식**: `frames.jsonl` 한 줄의 모양은 아래와 같다.
  ```
  {"host_t": PC epoch 초, "port": "s0"|"s1", "raw": "{\"t\":\"tof\",\"ms\":ESP32 millis,\"seq\":센서별 frame_seq,\"w\":8,\"h\":8,\"d\":[64 mm, -1=타깃 없음],\"st\":[64 상태값],\"flags\":펌웨어 방향}"}
  ```
  `tof_live.py` 녹화와 같은 형식이라 PC 에서 모델에 다시 흘릴 수 있다:
  `python tof_live.py --ports frames.jsonl@s0,frames.jsonl@s1 --model posture_net.onnx`.
- **유효 칸**은 상태값 5·6·9·10 이고 거리 ≥ 0 인 칸이다(`src/posture_net.h` `zoneValid` 와 같다). 모델 입력 채널 0 = 거리/4000, 채널 1 = 유효 마스크.
- **방향**: `/raw` 는 펌웨어가 이미 장면 방향으로 돌려 보낸 값이다(flags b0 flip_rows, b1 flip_cols = "이미 적용함"). 받는 쪽에서 더 뒤집지 않는다.
- **시간**: 프레임 간격은 ESP32 millis 로 잰다(PC 폴링 지연과 무관). 놓친 프레임은 seq 갭으로 세고, 연속 프레임 지표(프레임차·이동평균)에서 뺀다.
- **폴링**: 중계기는 응답마다 연결을 닫는다. 그래서 `/raw` 폴러 3개를 엇갈려 돌린다.
  ssh 두 홉으로 요청 하나가 0.25 s 걸려도 놓침은 약 2 %(폴러 1개면 약 22 %, 자가 시험 [7]).
- **기존 도구**: `pc/tof_noise.py`(10-17)는 요약만 남기고 원본을 버린다. 이 도구가 그 절차(`PLACEMENT_BASELINE_NOISE_PROCESS.md` §2)를 대신한다.
- **자가 시험**: `selftest` 는 아래 경우로 지표와 판정이 맞는지 본다.
  - 흰 잡음·AR(1) 잡음·깜빡임 칸
  - 거리 3개 맞춤, 움직인 녹화 제외
  - 흔들리는/안 흔들리는 가짜 사람과 빈 자리 기준 책상 칸 제외
  - 가짜 중계기 HTTP, 느린 터널, 멈춘 ESP32
  - 안내 진행(Enter·r·s·q)
