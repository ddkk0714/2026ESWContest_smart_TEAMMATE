# ToF 벽 잡음 실측 결과 (2026-10-24)

`WALL_NOISE_TEST.md` 의 `session` 으로 처음 잰 실측 잡음 기준이다.
HW(렌즈 앞 커버·센서 모듈·펌웨어 측정 설정)가 바뀌면 벽 60 cm 5분만 다시 재서 아래 표와 비교한다.

- 조건: 흰 콘크리트 벽, 천장 형광등, 지그 위로 약 25°(정면은 벽을 똑바로, 시야엔 벽만), 벽 45 / 50 / 60 cm 각 5분.
- 보드: Pi 4 자세 서비스(모델 `opt_l8_c256`) + 중계기(`relay.sh`), ESP32 USB 직결. 0x05 flags=3.
- 원본: [`dataset/tof_wall_noise/session_20261024_230205/`](../../../dataset/tof_wall_noise/README.md).
  - `frames.jsonl`(센서 원본 8×8 전부), `state.jsonl`(1 s `/api/state`), 녹화별 `report.json`·`summary.md`, `SESSION.md`·`fit.md`.
  - 같은 내용의 zip 이 Release [`tof-wall-noise-20261024`](https://github.com/ddkk0714/2026ESWContest_smart_TEAMMATE/releases/tag/tof-wall-noise-20261024) 에도 있다.

## 결론

1. **센서 잡음은 drowsy 과다의 원인이 아니다.**
   - 칸 흔들림 σ 는 1.8~2.1 mm, 끄덕임 대역(0.2~1 Hz)은 0.6~0.75 mm 다. 실제 고개 끄덕임(수 cm)보다 수십 배 작다.
   - 벽만 보는 15분 동안 모델 출력은 `misplaced` 100 %, `drowsy` 0 이었다(평활·순간 모두).
2. **보드 모델이 학습한 잡음과 실측이 같은 크기다.**
   - `opt_l8_c256` 의 `l8_params_v4.json` 은 σ/d 0.004~0.0065, 바닥 1 mm, dropout 0.001~0.006 이다.
   - 실측은 σ/d **0.0032~0.0039**, dropout 0 으로, v4 범위의 아래쪽 끝이다. 학습 잡음이 실제와 같거나 약간 크다 → 센서 잡음 설정은 바꿀 필요가 없다.
   - 시뮬 기본값 `L8Params(sigma0_mm=3, sigma1_mm=4)` 와 비교하면 실측은 그 절반이다.
3. **연속 프레임이 반대로 흔들린다**(1 프레임 자기상관 −0.25~−0.43).
   - 그래서 3프레임 평균(`mean3`)만으로 σ 가 절반(약 1 mm)이 된다.
   - 졸음 문제와는 무관한 크기다. 시뮬은 이 반상관을 모델링하지 않지만 영향은 작다.
4. **흔들림은 고르다.** 유효율 100 %, 깜빡임 칸 0, 튀는 값 0, 드리프트 0.04~0.15 mm/분이다.
   모든 칸이 함께 움직이는 성분은 약 1.2 mm 다.

## 거리별 맞춤

- 세 녹화의 칸별 점 384개로 맞췄다: `σ² = σ0² + (k·d)²` → **σ0 0.8 mm, k 3.3 mm/m**(σ/d ≈ 0.0033).
  - 시뮬 `L8Params` 형식(벽 반사율 0.7 가정)으로는 `sigma0_mm=0.8, sigma1_mm=2.8, dropout=0.0`.
- `SESSION.md`·`fit.md` 의 `L8Params(sigma0_mm=0.0, sigma1_mm=3.68)` 는 60 cm 녹화 하나로만 맞춘 값이다.
  - 도구가 놓침 10 % 초과 녹화를 뺐기 때문이다. 하지만 놓침은 σ 를 치우치게 하지 않으므로 **이 문서의 값을 쓴다.**
- 측정 범위가 48~65 cm 로 좁아 k 는 거칠다. 실사용 거리(50~80 cm)의 크기 비교에는 충분하다.

## 놓친 프레임 8.5~16 % — 측정 장비 쪽 손실

- ESP32 시각으로 본 프레임 간격은 198 ms 로 일정했다. 센서·펌웨어는 5 Hz 를 다 냈고, PC 가 일부를 못 받은 것이다.
- 놓침이 PC → Pi 5 → Pi 4 터널의 요청 지연과 같이 올랐다.

  | 지연 중앙값 | 놓침 |
  |---|---|
  | 89 ms | 8.5 % |
  | 119 ms | 12 % |
  | 169 ms | 16 % |

  중계기는 요청 하나를 받는 동안 UART 를 읽지 않는다. 터널이 느리면 그 사이에 같은 센서 프레임이 덮여 `/raw` 에서 보이지 않는 것으로 추정한다(미검증).
- σ 는 놓침에 치우치지 않는다. 연속 프레임 지표(프레임차·이동평균)는 이어진 구간만 쓴다.
- 다음 측정은 Pi 4 핫스팟 주소로 터널 없이 붙으면(`--raw http://<PI4>:8772`) 놓침이 줄 것으로 본다.

## 이 결과로 정해지는 것

- `PLACEMENT_BASELINE_NOISE_PROCESS.md` §1-3 의 장치 이동 문턱 `max(80 mm, 4·σ_noise)` 는 4σ ≈ 8 mm 라서 최소값 80 mm 가 그대로 쓰인다.
- 입력 필터(ESP32 3표본 평균·median3·EMA)는 잡음을 절반으로 줄이지만 drowsy 과다에는 효과가 없을 것이다. 우선순위를 낮춘다.

## 10-25 시뮬로 확인한 것 (보드 모델 `opt_l8_c256`, UBAI `pc_tilt_orient.py`)

- **기울기 25° 는 drowsy 오탐 원인이 아니다.** 시뮬 기울기별 48세션 × 300 s 결과:

  | 기울기 | 정확도 | drowsy 오탐률 | upright→misplaced |
  |---|---|---|---|
  | 10° | 0.64 | 0.040 | 0.20 |
  | 15° | 0.82 | 0.028 | 0.05 |
  | 20° | 0.83 | 0.026 | 0.05 |
  | 25° | 0.74 | 0.019 | 0.13 |
  | 30° | 0.55 | 0.012 | 0.29 |

  기울수록 drowsy 오탐은 줄고 misplaced 가 는다. **권장 장착은 15~20°** 다.
- **좌우 반전은 원인 후보다.** 10-19 실측(정면 80 cm)을 열(좌우) 뒤집어 채점하면 결과가 이렇게 나빠진다.
  - F1: 0.445 → 0.344
  - 바른자세를 drowsy 로 보는 비율: 0.077 → 0.146(2배)
- **실측 drowsy 오탐은 턱괴기에서 가장 많다.**
  - 정답 턱괴기의 50 % 를 drowsy 로 본다(거북목 12 %, 바른자세 8 %).
  - 정답 drowsy 는 67 % 를 misplaced 로, 16 % 만 drowsy 로 본다.
  - 실측 오탐률 0.11 은 시뮬 0.02~0.04 보다 커서, 사람·자세 쪽(손이 얼굴 앞에 오는 자세, 미세 흔들림, 옷·머리 반사) 차이로 본다.

## 남은 질문 (drowsy 과다의 원인 후보)

- ~~센서 잡음~~: 아니다(이 문서).
- ~~장착 기울기 25°~~: 아니다(위 시뮬 표). 다만 정확도는 15~20° 가 낫다.
- **좌우 방향**: 이번 녹화의 0x05 flags=3(행·열 뒤집기)은 10-22 재장착 뒤 기록(flags=1, FLIP_COLS=0)과 다르다.
  - flags 비트 뜻은 10-19 와 같다(b0 flip_rows, b1 flip_cols, 펌웨어가 이미 적용).
  - 그 뒤 COLS=1 로 다시 구웠거나 장착이 바뀐 것이라, flags 만으로는 맞는지 못 가린다.
- **사람·자세 쪽**: 턱괴기 → drowsy 혼동, 실제 사람의 미세 흔들림·반사. 사람 녹화가 있어야 가른다.
