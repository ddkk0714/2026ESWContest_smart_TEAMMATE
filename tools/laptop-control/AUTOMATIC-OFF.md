# ThinQ 시연 자동 OFF 1회

사용자가 자동 OFF 시험을 승인했다. 기존 수동 경로를 유지하며 이번 노트북 인증 세션에서만 동작한다.

## 시작

- 화면: http://127.0.0.1:19691/ (인증 19692, 센서 뷰어 18890)
- 인증 실행: 기존 수동 정책 명령에 `--allow-policy-post --policy-stage POWER_OFF --auto-off`를 추가한다.
- 새 터미널에서 PAT 숨김 입력 → 화면 새로고침 → 인증 연결 → 현재 상태 읽기.
- 실제 재실·활성 FSM, 본체 온라인·전원 ON, 외부 조작/예약 없음을 확인한다.
- V1.1 카드의 자동 OFF 영역에서 사전 동의 체크 → ‘자동 OFF 1회 시작’.
- 이후 실제 연속 부재 5초와 새 MQTT 표본 확인 → 새 Profile/State 확인 → OFF POST 1회 → 별도 GET readback.
- 추가 수락·개별 승인 없이 실행한다. 이 사전 동의가 해당 OFF 한 번의 승인이다.
- 시험 후 API 접수 / GET 일치 / 사용자의 본체 확인을 분리한다. 본체 확인 버튼은 ThinQ 팝업에 있다.

## 제한과 취소

- 기본 빌드와 기존 실행 명령에는 자동 OFF가 꺼져 있다. 자동 ON은 없다.
- 기존 policy, Session, GuardedSdk 및 전송 직전 검사를 재사용한다.
- Live POST 직전에 인증된 노트북 로컬 뷰어(127.0.0.1:18890)의 실제 재실·FSM을 다시 확인한다.
- MQTT 단절·stale·epoch/부팅 변경·세션 종료·수동 조작·대상 변경·인증 만료 시 차단한다.
- 부재 후 재실 복귀는 취소한다. ‘자동 OFF 취소’도 가능하나 이미 전송한 명령을 취소하지는 않는다.
- 자동 시도는 한 세션에서 한 번이다. 실패/timeout에도 재전송·복원하지 않는다.
- connection=unknown을 online으로 바꾸지 않는다. 실제 본체 온라인 확인을 사전 동의 조건으로 요구한다.
- 센서값은 최신 수신 표본 기준이다. 물리 상태 변화와 표본 수신 사이의 지연은 존재한다.
- 브라우저가 열려 있어야 자동 시험 tick이 전달된다. 브라우저 종료·절전 중 실행은 보장하지 않는다.
- 인증은 40분, 내부 개별 실행 challenge는 30초다. PAT는 메모리에만 존재하며 재시작 후 재입력한다.
- Pi 운영 코드·MQTT 발행·D-Bus/AppArmor 변경은 없다. 실제 자동 OFF 실기 성공은 아직 미검증이다.
