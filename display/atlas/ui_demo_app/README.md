# DESKMATE V47

## 블루투스 연결 규칙 (11-02 실기 기준)

세 기기를 한 보드에서 같이 쓰기 때문에 순서와 페어링 여부가 다르다. 아래가 지금 기준이고, 판별 기록은 각 판 메모에 있다.

| 기기 | 페어링 | 연결 |
|---|---|---|
| 스피커 `KLZS-L1` (A2DP) | **한다.** 앱이 `Adapter.Pair` 를 부르고, ATLAS 설정 앱에서 Paired 로 둔 상태로 확인했다(V38, 11-02 13:07) | 앱이 A2DP 로 |
| 램프 `KLZS-L1 app` (BLE GATT) | **하지 않는다.** SMP 미지원이라 설정 앱 페어링은 connected → timeout 으로 끝난다(10-12) | 앱이 GATT 로 |
| 선풍기 `DESKMATE-FAN` (BLE GATT) | **하지 않는다.** 페어링 없이 붙고, 잊히면 다시 찾아 붙는다(V35 `rediscoverDevice`) | 앱이 GATT 로 |

- **램프·선풍기를 설정 앱에서 연결해 두지 않는다.** 시스템이 GATT 링크를 잡으면 앱 `Connect` 가 `Already connected` 로 거절된다(V38 에서 원인 확인).
- **복원 순서는 램프 → 선풍기 → 스피커**(V40). 같은 칩의 A2DP 가 먼저 붙으면 램프 GATT 서비스 검색이 연달아 실패할 수 있다(11-02 13:22~13:25).
- 앱을 다시 켜면 이전 프로세스의 GATT 링크를 먼저 끊는다(V38). 그래도 `Already connected` 가 나오면 Pi 5 를 재부팅한다.

- **피로·졸음 상황**을 반복하면 다음 선호 방법을 보여준다.
- **부재** 입력은 경과 시간을 멈추고 5초 유예 후 종료한다. 유예 중 **돌아왔어요**로 복귀한다.

집중 중에는 프로필을 바꾸지 않는다. 종료 후 다른 프로필로 같은 입력을 재생해 비교한다.

## 시연 범위

(V17 까지의 범위. V18 은 보드에 이어지면 아래 'V18 책상(보드) 연결' 이 우선한다.)

센서, MQTT, HTTP, 블루투스, 카메라, 키 입력 수집, 원시 ToF, 파일 로깅,

## 시간과 원문 해석

UI 전용 값은 `assets/config/demo.json`에 있다. 제품 FSM 설정은 변경하지 않는다.
시연은 1초당 세션 60초, 작업 징후 지속 10초, 자동 진입 신뢰도 기준 0.7,
개인화 예시 0.82, 새 프로필 예시 0.56이다. 원문의 운영 기준 10분 지속과
재실 1분·3분·부재 5분은 실제 구현하지 않고 시연 입력과 5초 부재 유예로 대체한다.
상단 안내 5초, 상세 화면 10초, 위젯 30초는 실제 UI 대기 시간이다.

원문의 중복된 ‘작업 종료 화면’ 1·2단계는 흐름 설명에 맞춰
**집중 상세 / 어두운 집중 시계**로 구현하고, 종료 후에는 별도 요약을 띄운다.
백색 소음·카페 음악은 선호 선택과 문구만 표시한다.

## V11 변경

이름에 랜덤 한글 기본 별명을 미리 넣고 다른 별명 만나보기 버튼으로 다시 뽑을 수 있다.
이름 칸을 누르면 팝업 안에서 한글·영문 이름 키보드가 열린다. 두벌식 자모 조합,
복합 모음·받침·삭제·띄어쓰기·대소문자 전환과 16자 제한을 지원한다.
이름 지우기 X로 전체 삭제하며, 입력 완료는 키보드만 닫고 다음은 다음 질문으로 이동한다.
물리 키보드의 문자 입력·삭제도 처리한다.

Pi5 실기에서 Atlas 시스템 키보드가 열린 직후 약 30ms에 숨김 요청을 받는 현상을 확인했다.
타이밍 재시도와 기본 입력 제어 조정으로는 안정화되지 않아, 이름 입력에 한정해 시스템
키보드를 호출하지 않는 앱 내부 키보드로 교체했다. 기본 UI 색상과 글꼴을 사용한다.
V10 소스와 설치 앱은 보존한다. 외부 IME나 OS 설정은 변경하지 않았다.

## V12 개인화 세부 설정

기본 화면·집중 상세·멀티 위젯의 상단 톱니와 프로필 팝업의 나의 책상 설정에서 연다.
빛과 바람, 소리, 몰입, 나의 리듬 4개 탭으로 구성한다.
조명 시작 여부·밝기·빛 온도, 바람 시작 여부·1~3단계 세기, 피로 시 조명·바람 강도,
집중 소리 여부·종류·볼륨, 5~120분 집중 목표, 자동 시작·자동 환경 맞춤·시작 안내,
도움 순서, 프로필 이미지·작업·나이·수면·컨디션을 조정한다.
설정은 복사본을 편집해 저장 시 해당 프로필에만 적용하며 취소는 버린다.
집중 시작·피로 반응과 위젯의 목표·모의 음악 재생 상태에 연결한다.
새 프로필은 자동 맞춤이 켜져 있어도 충분히 알아가기 전에는 확인을 거친다.
모든 값은 UI 시연과 메모리에만 적용되며 실제 조명·바람·음악은 제어하지 않는다.
이 버전은 DESKMATE 상단 로고를 유지한다. 로고 제거는 다음 V13에만 적용한다.

## V14 문구와 화면 전환

제품 화면·툴팁·보고서·앱 표시 이름의 시연·데모·예시 표시를 제거했다. 새 앱 표시 이름은 DESKMATE V14다. 앞으로도 해당 표현을 제품 UI에 추가하지 않도록 AGENTS.md에 기록했다. 메인 화면·위젯 상세·설정 탭·프로필 팝업 전환에 280ms 페이드와 작은 이동 효과를 적용했다. 이전 화면은 전환 중 터치와 접근성 읽기를 차단하며 애니메이션 최소화 설정을 따른다. 기존 시스템 팝업의 진입·종료 효과와 프로필 질문 전환도 유지한다. UI-only 하드웨어 경계와 메모리 저장 방식은 변경하지 않는다.

## V15 페이드 스루 전환과 제안 카드 닫힘

공통 화면 전환을 페이드 스루로 바꿨다. 이전 화면이 약 105ms 동안 먼저 사라지고, 새 화면은 300ms 전환의 35% 지점부터 92%에서 100% 크기로 커지며 나타난다. 메인 화면·위젯 상세·설정 탭·프로필 팝업이 같은 전환을 쓴다. 터치·접근성 차단과 애니메이션 최소화 설정은 유지한다. 피로 제안 카드는 `다른 방법`·`좋아요`·`도움 됐어요` 중 하나를 누르면 바로 닫히고 답변 문구만 상단에 잠깐 표시한다. 이전에는 답변 문구를 제목으로 한 카드가 버튼과 함께 5초 동안 남았다.

## V16 가로 슬라이드 전환

V15의 제안 카드 수정은 그대로 두고 공통 화면 전환만 가로 슬라이드로 바꿨다. 각 전환 지점이 화면 깊이(`order`)를 넘긴다. 더 깊은 화면으로 가면 새 화면이 오른쪽에서, 돌아가면 왼쪽에서 들어오고 이전 화면은 반대쪽으로 함께 밀려난다. 전환 시간은 320ms다. 메인 화면은 홈·집중·상세·멀티 위젯·리포트 순서, 설정은 탭 순서, 프로필 팝업은 선택→등록, 멀티 위젯은 홈→목록→기기 상세 순서다. 같은 깊이끼리는 앞으로 가는 방향으로 처리한다. 영역 밖으로 그려지지 않게 잘라 내고, 터치·접근성 차단과 애니메이션 최소화 설정은 유지한다.

## V17 밝기 디졸브 전환

움직임·크기 변화 없이 화면이 스르륵 바뀌도록 공통 전환을 디졸브로 바꿨다. 이전 화면은 500ms 동안 서서히 흐려지고 새 화면은 같은 시간 동안 서서히 나타난다. 둘 다 시작과 끝이 부드러운 easeInOut 곡선을 쓴다. V16의 방향용 `order` 값은 제거했다. V15의 제안 카드 수정, 터치·접근성 차단, 애니메이션 최소화 설정은 유지한다.

V17 의 화면·글꼴·전환·카드 규칙은 그대로 두고, 보드에 이어지면 화면이 **실제 책상 상태**를 따라가게 했다.

앱 ID: `com.atlas.app.deskmate_ui_v18`, 표시 이름: **DESKMATE V18**, 실행 파일 `deskmate_ui_v18`.
V18 부터 ID 에서 `demo` 를 뺐다(보드에 이어지는 제품 화면이라). V17 이하 ID 는 그대로 보존한다.

### 두 앱 구성: 화면은 V18, 블루투스 실행은 deskmate_display

| 앱 | 하는 일 |
|---|---|
| **DESKMATE V18** (`com.atlas.app.deskmate_ui_v18`) | 사용자가 보는 화면. 상태·제안 카드·프로필·장치 위치. 기기 제어 명령은 보내지 않는다 |
| **DESKMATE** (`com.atlas.app.deskmate_display`, `ui_env_app`) | 블루투스 무드등·선풍기 실행(`control/cmd` → GATT → `control/result`). **Pi 5 에서 계속 켜 둔다** |

V18 은 블루투스·오디오 권한이 없다(`required_permissions` 비어 있음). 무드등·선풍기가 실제로 움직이려면
deskmate_display 가 실행 중이어야 하고 그 앱 블루투스 탭에서 기기가 골라져 있어야 한다. 화면 앞에는 V18 을 띄운다.
두 앱 모두 같은 질문(`interaction/request`)을 받는다. V18 에서 답하면 hub 는 그 질문을 닫고, 뒤에 있는
deskmate_display 가 나중에 보내는 `timeout` 은 질문 ID 가 이미 닫혀 hub 가 무시한다.

### 연결 설정

톱니바퀴(나의 책상 설정) → **연결** 탭에서 보드(Pi 4 Mosquitto) 주소와 포트(기본 1883)를 적고 **연결하기**.
주소 입력은 앱 내부 키보드(숫자·점·영문 소문자, `name_keyboard.dart` 의 `HostKeyboard`)를 쓴다 — Pi 5 에서
시스템 키보드가 열리자마자 닫히는 문제(V11) 때문이다. 연결 정보만 기기에 저장한다
(`$DESKMATE_CONFIG_DIR/ui_connection.json` → `$XDG_CONFIG_HOME/deskmate_ui/connection.json` →
`$HOME/.config/deskmate_ui/connection.json` → `/tmp/deskmate_ui/connection.json` 중 처음 쓸 수 있는 곳).
기본은 빈 주소 = 연결하지 않음. 상단 프로필 버튼 왼쪽의 작은 점이 연결 상태다(초록 = 이어짐, 회색 = 찾는 중,
노랑 = hub 가 offline 을 알림). 주소가 비어 있으면 점도 없다.

### 홈 하단 · FSM 흐름 대응

| 화면 | 보드 값 | 규칙 |
|---|---|---|
| 공기 | `sensor_summary.co2_ppm` | `assets/config/co2_bands.json` 등급 · ppm (예: "나쁨 · 1180 ppm") |
| 실내 | `temp_c` · `humidity_pct` · `lux` | 받은 것만 "24.4° · 51% · 320 lx" |
| 자세 | `sensor_summary.tof.posture` | upright 바른 자세 · lean_forward 앞으로 기울어짐 · forward_head 고개가 앞으로 나옴 · head_down 고개 숙임 · recline 뒤로 기댐 · face_down 엎드림 · chin_rest 턱 괴기 · lean_left/right 왼쪽/오른쪽으로 기울어짐 · drowsy 졸린 자세 · misplaced 장치 방향 확인. `present=false` 면 자리 비움 |

| 집중 시작 | `FOCUS_*` 로 들어옴 | 자동 시작이 켜져 있으면 집중 화면, 꺼져 있으면 기존 시작 제안 카드 |
| 쉬는 중 | `REST` | 집중 상세가 "잠깐 쉬어가는 중이에요", 경과 시간 멈춤, 멀티 위젯 캐릭터는 쉬는 표정 |

값이 없으면 숫자를 지어내지 않고 "살펴보는 중" 으로 둔다. 보드 상태를 따라 시작한 집중의 경과 시간은 실제 시간(1초=1초)이다.

### 제안 카드

`interaction/request` 의 `kind` 와 `data` 로만 띄운다(FSM 상태로 거르지 않는다). 답하면 바로 닫히고 답변 문구만 위에 5초(V15 규칙).
`data.explanation` 이 있으면 카드 본문이 된다. `expires_in_s` 가 지나면 닫고 `timeout` 을 보낸다(ui_env_app 과 같음).

| kind | 제목 | 버튼(reject / accept) | 닫힘 |
|---|---|---|---|
| `posture_suggest` | 자세를 가볍게 바로잡아 볼까요? | 나중에 / 해볼게요 | 응답·만료, 또는 hub 가 ACTION_* 를 벗어날 때 |
| `env_suggest` | 환경 플래그에 따라(잠깐 환기해 볼까요? 등). 정책이 창문 환기를 골랐으면 창문 문구 | 괜찮아요 / 좋아요 | 위와 같음 |
| `break_suggest` | 잠깐 쉬어 가는 건 어떨까요? | 조금 더 할게요 / 쉬어 갈게요 | 위와 같음 |
| `checkin_suggest` | 지금 피곤하세요? | 아니오 / 예 | 응답·만료만(FSM 상태와 무관) |

### 프로필 → hub (`deskmate/profile/user`, retain)

envelope `{"schema_version":"1.0","ts","node":"pi5-ui","boot_id","seq","data":{…}}`. 프로필을 만들거나(마지막 질문 뒤),
설정에서 저장하거나, 다른 프로필을 고를 때, 그리고 연결될 때마다 지금 프로필을 다시 보낸다.

| `data` 키 | 앱에서 | 대응 |
|---|---|---|
| `profile_id` | 프로필 생성 시 난수 | `p` + 16 hex. 이름과 무관. 복사본·수정본도 같은 값 |
| `age_band` | 프로필 질문 4 "몇 살" · 나의 리듬 탭 나이 | <20 `10s` · 20대 `20s` · 30대 `30s` · 40대 `40s` · 50+ `50s+` |
| `sleep_hours` | 질문 5 "얼마나 잠을" · 나의 리듬 탭 수면 시간 | 정수 시간 |
| `bedtime` | 나의 리듬 탭 "보통 잠드는 시각"(21:00~03:00, 30분 단위) | `HH:MM`, 기본 `23:30`(hub `sleep.default_bedtime`) |
| `wake_time` | 계산 | `bedtime + sleep_hours` |
| `light_pref` | 빛과 바람 탭 "집중 시작할 때 조명 켜기"·"원하는 밝기" | 조명 끔 또는 밝기 <40% `low` · <70% `mid` · 그 이상 `high` |
| `sound_pref` | 질문 7 소리 · 소리 탭 "소리 함께 듣기"·볼륨 | 무음/끔 `off` · 볼륨 <34% `low` · <67% `mid` · 그 이상 `high` |
| `wind_pref` | 빛과 바람 탭 "바람 켜기"·"바람 세기" | 끔 `off` · 1단계 `low` · 2 `mid` · 3 `high` |
| `focus_help` | 질문 6 "졸릴 때 무엇부터" · 몰입 탭 도움 순서 | 순서대로 조명 `light` · 선풍기 `wind` · 알림 `sound`(알림음). hub 어휘는 `light·wind·sound·voice·break` — 앱에 음성 안내·휴식을 고르는 항목이 아직 없어 `voice`·`break` 는 나오지 않는다 |
| `placement` | 질문 9 "장치를 보통 어디에 두나요?" · 나의 리듬 탭 "장치를 두는 곳" | `left` · `center`(기본) · `right` |

이름·이미지·작업(직업)·오늘 컨디션은 보내지 않는다.

### 프로필 저장(Pi 5)

hub 는 사람별 학습을 `profile_id` 로 묶는다. 실행마다 id 가 바뀌면 학습이 처음부터 시작되므로 V18 은 프로필과 고른 프로필을
Pi 5 에 저장한다: `$DESKMATE_CONFIG_DIR/ui_profiles.json` → `$XDG_CONFIG_HOME/deskmate_ui/profiles.json` →
`$HOME/.config/deskmate_ui/profiles.json` → `/tmp/deskmate_ui/profiles.json` 중 처음 쓸 수 있는 곳, 임시 파일 → rename 으로 원자적으로.
담는 것: `profile_id`·별명·이미지·작업·확인 횟수·나이·수면·잠드는 시각·소리·도움 순서·컨디션·장치 위치·4개 탭의 선호 값.
첫 실행에는 기본 프로필을 바로 저장해 그 id 도 다음 실행에 같다. 파일이 깨졌으면 기본 프로필로 시작하고, 항목 하나가 깨지면 그 항목만 버린다.
별명·이미지는 이 파일에만 있고 MQTT 로는 보내지 않는다. 종료 요약의 "오늘 피곤했나요?" 선택·화면 기록은 저장하지 않는다.

### 장치 위치 질문

프로필 등록의 마지막(9/9) 질문 "장치를 보통 어디에 두나요? / 앉은 자리에서 봤을 때". 위에서 본 책상 그림(모니터·사람·
세 자리, 양옆은 모니터 끝 근처 정면에서 약 40°)과 1 왼쪽 · 2 가운데 · 3 오른쪽. 답하면 프로필에 넣고
`POST http://<보드 주소>:8771/api/placement` 를 보낸다. 결과("장치 위치를 왼쪽으로 맞췄어요." 또는 실패 한 줄)는
환영 화면에 4초 보인다. 연결 주소가 없으면 보내지 않는다. 설정 나의 리듬 탭에서 바꿔 저장해도 같은 요청을 보낸다.

### 보드에 닿지 않을 때

주소가 비었거나, 브로커에 닿지 않거나, `state/phase` 가 45초 넘게 없으면 V17 과 같은 메모리 동작으로 돌아간다
(5초마다 재연결). 화면에 "연결 안 됨" 같은 큰 표시는 하지 않고 상단 점만 회색이 된다. 진행 중인 집중은 그대로 이어진다.

### 이번 버전에서 하지 않은 것

- V18 은 `control/cmd` 를 보내지 않는다. 멀티 위젯 조명 슬라이더는 화면 안의 값만 바뀐다(다음 버전 후보).
- 날씨 타일은 아직 기존 그림을 쓴다. 받은 날씨는 연결 탭 한 줄에만 보인다.
- 종료 요약의 "오늘 피곤했나요?" 선택은 hub 로 보내지 않는다(대응 토픽 없음).
