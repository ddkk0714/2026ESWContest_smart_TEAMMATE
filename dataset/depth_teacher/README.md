# D435if 자세·졸음 판단 파이프라인 (Teacher)

최종 목표: **L9(VL53L9CX ToF)만으로 자세/졸음 판단**.
이 단계: Intel RealSense D435if 하나로 앉은 자세와 졸음을 판단하고, 그 결과를 L9 학습용 정답 라벨로 쓴다.

> **제품에 들어가지 않는 오프라인 라벨링 도구다.** 깊이 카메라는 개발 PC에서 학습 데이터의
> 정답을 만들 때만 쓰고, 보드에는 배포하지 않는다. 녹화본·세션 CSV(`data/`)와 모델(`models/`)은
> 커밋하지 않는다.

```
D435if RGB + Depth ─▶ MediaPipe 2D 랜드마크 ─▶ Depth로 3D 복원 ─▶ IMU 중력 기준 월드 좌표
   ─▶ 특징값(목 각도, 머리 전방 거리, 고개 pitch, 어깨 높이/기울기 …)
   ─▶ 캘리브레이션(준비 5초 + 바른 자세 8초) 대비 변화량 + 규칙 + 시간 평활 ─▶ 라벨 (frames.csv, 호스트 시간 포함)
```

## 측정 지점

- **머리**: 얼굴 피부 위 점(이마 10, 턱 끝 152, 광대 116/345). 귀는 머리카락에 덮이면 가시성이 떨어지고 깊이도 머리카락 표면이 잡혀서, 얼굴을 놓쳤을 때만 예비로 쓴다.
- **몸통 깊이**: 어깨선 아래 가슴 중앙(`torso`). 검은 옷과 검은 사무용 의자의 경계가 애매해도 등받이가 섞이지 않는다.
- **어깨**: 높이, 폭, 기울기는 랜드마크 픽셀로 잰다. 깊이는 목 쪽으로 옮겨 가며 재고, 몸통과 8cm 이내인 값만 받는다(뒤에 있는 등받이는 버린다).
- **팔**: 팔꿈치, 손목, 손가락 끝(검지, 새끼, 엄지)을 양쪽 다 쓴다. 턱 괴기 판정용이다.

## L9 측정 요소 배제

눈 깜빡임처럼 L9로 직접 측정 가능한 얼굴 미세 신호는 **계산 자체를 하지 않는다** (`config.yaml`의 `excluded_signals`).

- FaceLandmarker의 blendshape(눈 깜빡임, 입 벌림 계수) 출력을 끈다.
- Pose의 눈/입 랜드마크와 Face mesh의 눈/입 영역을 쓰지 않는다. 얼굴에서는 이마, 턱 끝, 광대만 쓴다.
- 졸음은 머리 동역학(끄덕임, 고개 떨군 채 정지, 흔들림)만으로 판단한다.

## 라벨

| 라벨 | 판단 근거 (기준 자세 대비) |
|---|---|
| `chin_rest` 턱 괴기 | 손(손목/손가락)과 턱 사이 3D 거리 10cm 이내 + 그 팔 팔꿈치가 어깨 아래. 15cm 넘게 멀어져야 해제. 팀 `camsvc/posture_pose` 정의의 3D판 |
| `forward_head` 거북목 | 목 각도 +12° 또는 머리가 몸통보다 4cm 이상 앞으로 |
| `head_down` 고개 숙임 | 이마-턱 pitch +9° 또는 코가 광대선보다 2.5cm 이상 아래로 |
| `slouch` 구부정 | 어깨 높이 4cm 이상 하강 (어깨가 앞으로 말리는 구부정은 아직 못 잡음) |
| `lean_forward` 상체 앞으로 | 몸통이 카메라 쪽으로 8cm 이상 |
| `lean_left` / `lean_right` | 어깨 중심 6cm 이상 이동 또는 어깨 기울기 8° 이상 |
| `head_tilt` 고개 갸웃 | 광대-광대 roll 12° 이상 |
| `too_close` | 얼굴-카메라 거리 40cm 이하 (절대값) |
| `drowsy` 졸음 | 60초 안에 끄덕임 2회 이상, 또는 고개 떨군 채 5초 이상 정지. 판정 후 5초 유지 |

`posture` 열은 위 플래그를 `priority` 순서로 고른 단일 라벨이다 (해당 없으면 `normal`, 사람/어깨를 못 찾으면 `invalid`). 임계값은 모두 `config.yaml`에 있다.

## 설치

Python 3.11 (pyrealsense2 휠이 있는 버전), Windows에서 검증:

```
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

Windows Store 앱 폴더처럼 가상화되는 경로에는 가상환경을 만들 수 없다.

MediaPipe 모델은 처음 실행할 때 `models/`에 자동으로 받는다.

## 사용법

```
python run.py --user soyeon                  # 실시간 (기준 자세가 없으면 준비 5초 + 측정 8초)
python run.py --user soyeon --recalibrate    # 기준 자세 다시 측정 (실행 중 c 키도 가능)
python protocol.py --user soyeon --record-bag --video   # 검증 시나리오 녹화 + 자동 평가
python relabel.py data/sessions/<세션> --eval  # config 수정 후 재처리 없이 다시 라벨링·평가
python run.py --user soyeon --bag data/sessions/<세션>/raw.db3   # 녹화 원본 재처리
python tools/inspect_session.py data/sessions/<세션>
python tools/replay_eval.py data/sessions/<프로토콜 세션>   # 랜드마크/깊이 코드 변경 후 녹화본 재처리·평가
python evaluate.py data/sessions/<세션>/frames.csv --skip 2  # 각 단계 처음 2초(반응 시간) 제외
```

## '완벽'을 위한 반복 루프

1. `protocol.py`로 안내된 자세를 취하면, 단계별 정답(`gt_posture`, `gt_drowsy`)이 함께 기록된다.
2. 자동 평가 리포트(`report_frames.txt`)를 본다: 혼동행렬, 플래그 재현율, 정상 구간 오탐률, 졸음 재현율/정밀도.
3. `config.yaml` 임계값을 조정한 뒤 `relabel.py --eval`로 바로 재평가한다 (특징값이 CSV에 저장돼 있어 영상 재처리가 필요 없다).
4. 여러 사람과 여러 세션으로 반복한다. 랜드마크 검출 방식 자체를 바꾸면 `--record-bag` 원본으로 재처리한다.

## 출력 (`data/sessions/<user>_<시각>_<tag>/`)

- `frames.csv`: 프레임마다 `t_host`(epoch 초, **L9 데이터와 시간 동기화 키**), 3D 랜드마크, 특징값, 라벨.
- `meta.json`: 카메라 내부 파라미터, IMU 중력 방향, 기준 자세, 설정 스냅샷.
- `raw.db3` (`--record-bag`, RealSense SDK 2.58+ rosbag2 형식, 약 2.7GB/분), `color.mp4` (`--video`, 검토용).

## 설치/환경 메모

- 카메라를 위아래 뒤집어 놓아도 IMU가 감지해서 영상을 180° 돌린다. 60° 이상 기울면 수평으로 가정한다.
- Windows에서는 `mediapipe`를 import한 프로세스가 IMU 프레임을 받지 못해서, IMU 측정은 별도 프로세스에서 한다 (`measure_up_vector_isolated`).
- Windows 카메라 앱 등 다른 프로그램이 카메라를 쓰고 있으면 프레임이 오지 않는다.
- 월드 좌표: X = 사용자 왼쪽(+), Y = 위(+), Z = 카메라로부터 수평 거리.

## 검증 현황 (2026-10-04, 1인 · 프로토콜 2회)

`protocol.py` 녹화 2회(1차 `144652`, 2차 `152005`)를 현재 코드로 다시 라벨링한 결과다.
각 단계 처음 2초(자세 전환 반응 시간)는 채점에서 뺐다.

| 항목 | 2차 결과 | 메모 |
|---|---|---|
| 자세 단일 라벨 정확도 | 79% | 1차 72% (1차는 기준 자세가 정상보다 8~19cm 앞에서 잡힘) |
| 턱 괴기 | 100%, 정상 오탐 3% | 팀 `display/atlas/camsvc/src/posture_pose` 정의를 3D로 |
| 고개 숙임 / 구부정 / 상체 앞으로 | 97% / 76% / 78% | |
| 거북목 | 58% | 자세 진입에 약 4초 걸림. 진입 뒤에는 +27°로 안정적으로 잡힘 |
| 왼쪽 기울임 | 0% | 상체 대신 고개만 기울여 고개 갸웃으로 잡힘 → 프로토콜 문구 수정 |
| 졸음 (프레임) | 재현율 47%, 정밀도 93% | 1차 67%, 98%. 끄덕임 = 몸통은 그대로, 고개만 |
| 측정 불가 | 12.9% | 어깨 깊이 대체값 적용 전 수치 |

**주의.** 일부 임계값(구부정 2cm, 끄덕임 몸통 한도, 우선순위)은 이 두 녹화를 보고 맞췄다.
같은 녹화로 낸 점수라 실제보다 좋게 나왔을 수 있다. 새 녹화와 다른 사람으로 확인해야 한다.

**아직 검증 안 한 것**
- 어깨 깊이 대체값(몸통 깊이): 합성 테스트만 했다. `tools/replay_eval.py`로 녹화본 재처리가 필요하다.
- 새 프로토콜 단계(좌우 기울임 문구, 키보드 힐끗 보기 = 졸음 오탐 확인).
- 졸음 지속 판정은 끄덕임 뒤 떨군 상태만 잇는다. 끄덕임 없이 곧바로 깊이 조는 경우는 못 잡는다
  (숙인 채 정지는 책상 보기와 구분되지 않는다).
