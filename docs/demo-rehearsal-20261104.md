## 2. 고쳐서 확인된 것 (V52)

- **앱이 스스로 음악·램프를 켜던 동작 없음.** A2·B2·A6·B6 에서 hub 가 보낸 것 외에 앱이 따로 켠 것이 없었다.
- **빠른 진행 스위치**가 hub 빠른 시연을 함께 켠다.
- **사람이 바뀌면 앞사람 기기를 되살리지 않는다.**

## 3. 시연 전에 꼭 정할 것

### 3-1. B4(B 엎드림)가 안 된다 — 결정 필요

- 원인: 시연 프로파일 `demo-b` 의 `ingest.tof.min_confidence_by_label.face_down: 0.99`. 깨어서 글 쓰는 사람을
  엎드림으로 오판하는 것(중앙값 0.87)을 막으려고 둔 하한이다.
- B 의 엎드림 확신도는 **0.43~0.90**(A 처럼 엎드려도 최고 0.90). 0.99 에 못 미쳐 '모름'(증거 0)으로 버려지고,
  2등인 턱 괴기가 1등이 되는 순간에만 피로가 올라 **턱 괴기 → 안내 카드**로 끝나거나, 자세 증거가 없어 **환경 개입**으로 빠진다.
- 방법: (가) hub 하한을 0.85 쯤으로 낮춘다 — 바르게 앉아 글 쓸 때 엎드림 오판 위험이 다시 생긴다, 박소연 확인 필요.
  (나) 대본에서 엎드리는 역할을 확신도가 잘 나오는 사람(A)에게 맡긴다.

### 3-2. 뒤로 젖히면 자리 비움으로 읽힌다

- A2 에서 음악이 켜지고 11 s 뒤, 레이더가 사람을 **178 cm · 움직임 없음**으로 보며 `present:false`(근거 `mmwave_room`) →
  빠른 시연의 자리 비움 5 s 끄기로 **음악·램프·선풍기가 전부 꺼졌다.** 바르게 앉자 같은 사람이라 되살렸다.
- B2 첫 시도·리허설 끝 무렵에도 같은 일이 났다. 젖힘 도중 `pose=away` 가 되면 깨우기 대신 환경 개입으로 빠진다.
- 대응: **장치를 사람 쪽으로 당기고**, 젖힐 때 **등받이에 살짝만** 기댄다. 리허설에서 거리를 다시 잰다.

## 4. 진행 중 주의 사항

- **거북목·턱 괴기 카드가 뜨면 바로 바르게 앉는다.** 오래 끌면 ESCALATE → 환경 개입(선풍기·램프 제안)이 나간다.
  대본의 "30초" 보다 짧게.
- **엎드릴 때 턱이 손에 닿지 않게.** 턱 괴기로 읽히면 깨우기 대신 카드가 나온다.
- **바른 자세에서 고개를 숙이지 않는다.** A1 에서 졸림 확률이 0.38 까지 올랐다.
- **사람 바꾸기는 B 가 앉기 전에.** 앉은 뒤 10 s 가 지나면 A 의 기기가 되살아난다.
- **빠른 시연은 켠 뒤 30 분이면 저절로 꺼지고, hub 가 다시 켜져도 꺼진다.** 시작 직전에 켜고 화면 구석 '빠른 시연' 배지를 본다.
- **보드 hub 를 다시 깔지 않는다.** 지금 빌드는 어떤 브랜치에도 없다. main 으로 다시 깔면 사람마다 다른 기기 규칙(demo_wake)이 사라진다.
- **회복 단계에 들어가면 음악이 꺼지고 램프가 회복 색(옅은 하늘색)으로 바뀐다.** 앱의 원래 동작이다. 설명에서 "음악을 계속 틀어 둔다"고 하지 않는다.

## 5. 대본 문구에서 바꿀 것

- **"좋아하는 소리로 카페 음악"** → 앱에 카페 음악 곡이 없다(클래식 6곡). "좋아하는 음악" 으로.
- **"피곤할 때 조명 색이 사람마다 다르다"** → V52 에서 동작하지만 **설정 값이 같으면 같은 색이다.**
  오늘 네 프로필 모두 '빛의 온도' 0.25 그대로였다(바꿨는데도 저장이 안 됐는지 확인 필요).
  태환은 따뜻하게(왼쪽), 민경은 시원하게(오른쪽)로 저장했는지 시연 전에 `profiles.json` 의 `fatigue_warmth` 로 확인한다.

## 6. 재확인(01:31~01:38)에서 더 알게 된 것

- **사람별 '피곤할 때 색' 실기 확인**: 민경이 뒤로 젖히자 hub 는 무드등 +60 % 만 보냈고, 앱이 그 사람 색을 덧칠해
  **주황빛**이 됐다(값 0.25). 음악은 나오지 않았다.
- **'빛의 온도' 슬라이더가 둘이다.** '하루를 감싸는 빛' 카드의 **빛의 온도**는 평소 조명(warmth)이고,
  맨 아래 '잠시 지칠 때의 환기' 카드의 **환기할 때 빛의 온도**(fatigue_warmth)가 피곤할 때 색이다. 리허설 때 앞의 것을 바꿔
  색이 같게 나왔다. 이름을 '피곤할 때 조명 색' 처럼 구분되게 바꾸는 것을 제안.
- **태환도 엎드림이 안정적이지 않다.** 엎드림 확신도 0.93~0.95 로 0.99 하한에 못 미쳐 환경 개입으로 빠졌다. A4 가 된 건
  그 순간 0.99 를 넘은 운이었다. **엎드림 장면은 A·B 모두 hub 하한을 낮추기 전엔 믿을 수 없다.**
- **기기가 켜진 뒤 같은 자세로 20 s 넘게 있으면** MONITOR → ESCALATE → 휴식으로 넘어간다(민경 젖힘: 조명 켠 뒤 25 s).
  대본의 '30초' 장면은 **기기가 켜지면 바로 바르게** 로 바꾼다.
- **엎드린 채 오래 있으면 휴식(REST, 최소 60 s)** 으로 넘어가며 음성 안내를 보내는데, 보드에 TTS 가 없어 실패한다
  (`tts_unavailable`) — 앱이 알림음·화면 안내로 대신한다. 휴식 동안은 새 개입이 안 나온다.
- **빠른 시연 30분 자동 꺼짐이 실제로 났다**(01:05:35 켬 → 01:35:40 `normal`). 앱의 '빠른 진행' 스위치는 켜진 채로 보이니
  **껐다가 다시 켜야** hub 에 다시 간다.
- **프로필 버튼은 집중 중엔 회색이다**(`main.dart` `m.active ? null`). 사람을 바꿀 땐 앞사람이 떠나 기기가 꺼진 뒤 바꾼다.
  **'빠른 진행'을 꺼서 바꾸지 않는다** — 끄면 hub 빠른 시연도 꺼져 B 장면이 느린 모드로 돈다.
- **회복 단계에 램프가 하늘색(80,180,255, 밝기 90)으로 바뀐다** — 앱의 원래 국면 조명. 발표자가 '회복을 알리는 색' 으로 짚는다.
- **자리 비움 끄기도 선풍기 쿨다운(300 s)을 시작시킨다.** 그 사이 환경 개입의 선풍기는 막힌다. 깨우기 규칙(demo_wake)은
  쿨다운을 무시하므로 B4 선풍기에는 영향 없다.

## 7. 아직 확인 못 한 것

- **선풍기 켜기**: B4 가 실패해 선풍기 **켜기**는 한 번도 나가지 않았다(끄기는 매번 성공).
- **램프 색과 음악 소리**: 명령 성공은 기록으로 봤지만 실제 색·소리는 눈·귀 확인이 필요하다.
- **사람마다 다른 색**: 두 사람의 '환기할 때 빛의 온도'를 다르게 저장한 뒤 한 번 더 본다(저장 자체는 정상 — 다른 슬라이더를 바꾼 것).
