## 1. 심박 졸음 규칙 — "ToF 정지 ∧ mmWave 심박 하락" [시뮬]

지금 hub 는 ToF 가 살아 있으면 mmWave 졸음 판정을 쓰지 않는다. 비교한 방식(모두 "ToF 정지 60 s ∧ 졸음 증거 → 자세 피로 증거 1.0"):
A = 펌웨어 `drowsy_state == DROWSY` · B = 펌웨어 내부 심박 하락 · **Bp** = hub 가 `heart_bpm` 으로 계산, 기준선 = 책상 재실 ∧ 깨어 움직일 때 심박(가만히 있으면 얼림) · **Bph** = Bp + `fatigue_hold_min_frac: 0.8`.

| 각본 (첫 개입 s / 놓친 실행) | off | A | B | Bp | **Bph** |
|---|---|---|---|---|---|
| 큰 끄덕임 (30~50°) | 685 / 1 | 685 / 1 | 685 / 1 | 685 / 1 | 694 / **0** |
| 약한 끄덕임 (15~25°) | — / **4** | 702 / 1 | 962 / 2 | 932 / 1 | 957 / **0** |
| 조용한 졸음 (4~10°) | — / **4** | 657 / 0 | 752 / 2 | 850 / 0 | 780 / **0** |
| **놓친 실행 합 (12 개 중)** | **9** | **2** | **5** | **2** | **0** |
| 깨어 독서 60 분 개입 | 0 | 4.5 | 2.8 | **0** | **0** |
| 독서 norelax(심박 안 내려감) 개입 | — | 3.5 | 2.0 | **0** | **0** |

- A 는 정지 3 분이면 DROWSY 라 독서 중 피로 확정이 난다. B 는 오래 졸면 하락이 기준선에 묻혀 놓친다.
- 켤 때 설정: `ingest.yaml mmwave.still_drowsy_and` → `enabled: true`, `mode: hr_down_presence_base`, `tof_motion_max_mm: 12`; `fsm.yaml timers.fatigue_hold_min_frac: 0.8`.

### 첫 개입이 왜 13~16 분이나 걸리나 [시뮬]

- 자세 가중 0.25 → 0.35 → 0.45 (Bph, 보드 EMA): 약한 끄덕임 957 / 957 / 957 s, 조용한 졸음 780 / 774 / 774 s, 큰 끄덕임 650 / 642 / 642 s, 헛개입 0 → **가중은 병목이 아니다.**
- 졸음 중 피로 점수는 이미 0.85(확정 0.70)인데, 규칙이 약 60 s 켜짐·60 s 꺼짐을 반복해 "180 s 중 80 %" 유지가 안 쌓인다. 꺼지는 이유는 ToF 정지 조건 — 시뮬 격자 움직임은 자세와 무관하게 4~7 mm 인데 한 tick 만 8.1·9.0 mm 가 나와도 정지 시각이 지워진다.

| ToF 정지 문턱 (Bph, 보드 EMA) | 8 mm | **12 mm** | 조건 없음 |
|---|---|---|---|
| 약한 끄덕임 첫 개입 | 957 s | **632 s** | 632 s |
| 조용한 졸음 | 780 s | 780 s | 780 s |
| 큰 끄덕임 | 650 s | 614 s | 614 s |
| 놓친 졸음 (12 개 중) | 0 | 0 | 0 |
| 깨어 독서 개입 (60 분) | 0 | 0 | 0 |

실기 ToF 잡음은 시뮬의 약 1/3(10-19 실측)이라 문턱은 실측 격자 움직임 분포로 정한다.

**실측으로 확인할 것**: C1001 심박을 스마트워치와 나란히 — 깨어 가만히 10 분 · 눈 감고 졸기 10 분 · 타이핑 10 분. "깨어 움직일 때 심박 − 졸 때 심박"이 4 bpm 을 넘는지.

## 2. CO₂ 환기 타이밍 규칙 (FSM 밖, `--vent-rule`) [시뮬]

v8 기준선에서 창문 환기가 한 번도 안 일어났다 — 환기 카드가 피로 **확정 뒤**에만 떠서 사람이 이미 졸고 있었다.
규칙: SCD41 1 분 평균 ≥ 1000 ppm 5 분 + 책상 재실 + 깨어 있음 + 창문 닫힘 → 창문 카드(비·눈·바깥이 더 더움·바깥 PM ≥ 36 이면 제외, 몰입 중이면 최대 10 분 기다림, ≥ 1400 이면 바로).

| 각본 (시드 1~3 평균) | 재실 중 CO₂≥1000 분 끔 → 켬 | CO₂≥1400 분 | 카드 수락/거절/무응답 | 수락한 카드: CO₂ → 15 분 뒤 |
|---|---|---|---|---|
| 대학생 하루 (가을) | **117.9 → 50.7** | 126.0 → 33.7 | 4 / 2 / 1 | 1430 → 498 |
| 수험생 하루 (겨울 −2 ℃, 5 분 환기) | **112.0 → 70.1** | 114.3 → 43.3 | 5 / 1 / 6 | 1400 → 856 |
| 저녁 요리 | **59.9 → 33.4** | 0 → 0 | 3 / 1 / 2 | 1087 → 508 |
| 대조: 개발자 하루(비) · 황사 | 카드 0 (제외 사유 기록) | | | |

- **피로 이득은 이 시뮬로 못 잰다**(졸음은 각본이 정하고 CO₂ 는 환경 가중 0.10~0.20). 수험생은 무응답이 많다(12 장 중 6).
- 곡선 원자료: [`data/vent_rule_co2_curves.json`](data/vent_rule_co2_curves.json)(각본 × 시드 × 끔/켬, 분 단위 CO₂·창문·재실·카드).
- GIF: [`img/vent_window_x30.gif`](img/vent_window_x30.gif) — 대학생 시드 1, 20~41 분, 깨어 있을 때 창문 카드 → 수락 → CO₂ 1230 → 484 ppm(30 배속).

## 3. FSM 실험 옵션 (기본값 = 지금 동작) [시뮬]

`timers.monitor_window_sec`(MONITOR 판정 창) · `elapsed.reset_on_rest`(휴식 뒤 경과 시간 초기화) · `timers.fatigue_hold_min_frac`(피로 유지를 "지난 hold 초 중 비율"로). PR #73 에도 같은 키가 들어 있다.

- 휴식↔격상 반복("강제 휴식 13 연속")의 원인은 MONITOR 1 tick 이 아니라 **경과 시간 신호가 휴식 중에도 계속 쌓이는 것**이었다(δ = 세션 시간 / 5400 s → 피로 점수 1.0 → 5 분마다 회복 실패).
  - 합성 개발자 하루 시드 1: 기본 휴식 31.8 분 / 강제 7 회 → 경과 초기화 25.0 / 5 → 판정 창 120 s + 초기화 10.0 / 2.
  - 개발자 하루 시드 2(MuJoCo+GRU): 강제 휴식 11 → 1, 휴식 51 → 5 분, 격상 14 → 3, 개입 16 → 6, 자세 정확도 0.73 → 0.88(강제 휴식이 사람을 자리에서 내보내지 않으니).
- 졸음 → 첫 개입이 10-22(205~221 s)보다 길어진 740~1318 s 의 원인: 코드가 아니라 장면(시드 1·3 배치에서 GRU 가 졸음↔다른 자세로 깜빡임) + 180 s **연속** 유지(점수가 한 번 내려가면 처음부터). 10-22 시드로 v8 코드를 다시 돌린 대조군은 대학생 202~220 s(10-22 204~210), 개발자 206 s(221), 수험생 416 s(397), a1 573 s(553) — 코드는 원인이 아니다.
- GIF: [`img/fsm_before_after_x30.gif`](img/fsm_before_after_x30.gif) — 왼쪽 지금 fsm.yaml(5 분마다 강제 휴식), 오른쪽 판정 창 120 s + 휴식 뒤 경과 초기화, 개발자 하루 72~97 분(30 배속).
