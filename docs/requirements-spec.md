# DESKMATE 요구사항 명세서

기준: 개발계획서 v2 · `DESKMATE_FSM-VER5` · 2026-08-28 팀 협의

## 1. 목적과 범위

DESKMATE는 카메라와 상시 음성 녹음 없이 책상 작업자의 재실·자세·키 입력 타이밍·환경 신호를 융합해 집중 저하와 피로 가능성을 추정하고, 조명·환기·휴식 개입을 자동 실행하거나 사용자에게 제안하는 로컬 스마트 가전이다.

1차 MVP 범위는 ESP32 센서 수집·전처리, MQTT 통신, Raspberry Pi 4의 규칙 FSM, Node-RED 모니터링, Raspberry Pi 5 Atlas UI의 상태 표시와 사용자 피드백이다. TFLite 분류기와 RL 정책 갱신은 1차 FSM이 단독으로 안정화된 후의 선택 범위다.

## 2. 시스템 경계

```text
VL53L5CX ToF ─┐
SEN0623 mmWave ├─> ESP32 1차 전처리 ─MQTT─> Pi 4 Mosquitto + Python hub ─> FSM/제어
SEN0536 CO2/온습도 ┤                         ├─> Node-RED 모니터링·로깅
SZH-EK070 조도 ─┘                         └─MQTT─> Pi 5 Atlas UI/스피커/터치
PC 키스트로크 타이밍 ──────────────┘                         └─< 사용자 피드백
```

- Node-RED는 MQTT 토픽을 구독하여 실시간 센서값, 유효성, 장치 상태, FSM 결과를 시각화하고 실험 로그를 저장한다.
- Python hub가 정규화·융합·FSM의 단일 기준 구현이다. Node-RED 재시작·오류가 FSM 판정을 중단시켜서는 안 된다.
- 통신과 값 계약은 [`mqtt-topics.md`](mqtt-topics.md), [`data-spec.md`](data-spec.md)를 단일 기준으로 삼는다.

## 3. 기능 요구사항

### 3.1 수집·전처리

| ID | 요구사항 | 수용 기준 |
|---|---|---|
| FR-SEN-001 | ESP32는 ToF, mmWave, CO₂·온습도, 조도 센서를 읽어 1차 필터링한다. | 센서별 표준 토픽에 명세된 주기로 30분 연속 발행한다. |
| FR-SEN-002 | ToF raw 8×8 배열은 일반 운영 MQTT에 발행하지 않고 재실·자세·모션·고개 노딩 특징으로 변환한다. | 운영 로그에 64-zone raw 배열이 없다. |
| FR-SEN-003 | PC 수집기는 키 내용이 아닌 dwell·flight·idle·correction 통계만 발행한다. | payload와 로그에 key code, 문자, 원시 타임스탬프 시퀀스가 없다. |
| FR-SEN-004 | 모든 센서 샘플은 값과 독립적인 유효성·신선도 정보를 제공한다. | 결측·범위 이탈·오래된 샘플이 `valid=false`로 구분된다. |

### 3.2 통신·Node-RED

| ID | 요구사항 | 수용 기준 |
|---|---|---|
| FR-COM-001 | ESP32·PC·Pi 4·Pi 5는 Mosquitto MQTT로 결합한다. | 각 장치를 독립 재시작해도 다른 장치가 비정상 종료하지 않는다. |
| FR-COM-002 | 센서 패킷은 `schema_version`, `ts`, `node`, `boot_id`, `seq`, `crc16`으로 스키마·순서·무결성을 판정한다. | 중복, 역순, CRC 오류, 스키마 불일치가 각각 로그로 남고 FSM 입력에서 제외된다. |
| FR-COM-003 | Node-RED는 raw topic과 hub 결과 topic을 대시보드에 표시하고 JSONL 로그를 남긴다. | 센서 값·`valid`·최종 상태·점수가 확인되며 Node-RED 종료 중에도 hub FSM이 작동한다. |

### 3.3 융합·FSM

| ID | 요구사항 | 수용 기준 |
|---|---|---|
| FR-FSM-001 | Pi 4는 30초 주기로 `C_fatigue`와 `C_focus`를 독립 계산해 VER5 FSM을 전이한다. | [`fsm-spec.md`](fsm-spec.md)의 전이 테스트가 통과한다. |
| FR-FSM-002 | baseline은 사용자별 자세·키스트로크·호흡 신호를 상대값으로 변환한다. | 사용자/거치 위치가 달라져도 baseline 재수행 후 동일 특징 범위를 출력한다. |
| FR-FSM-003 | ToF↔SEN0623은 고개 노딩·정적 자세·재실·모션·호흡을 교차 확인한다. | 한 센서만의 숙임으로 졸음을 확정하지 않는다. |
| FR-FSM-004 | SEN0536 CO₂·온습도↔SZH-EK070 조도는 환경성 피로 맥락과 개입 원인을 판정한다. | 환경 신호 단독으로 졸음을 확정하지 않고 `ACTION_ENV` 근거로 쓴다. |
| FR-FSM-005 | TFLite를 불러오지 못해도 1차 FSM은 단독으로 작동한다. | 모델 파일/런타임을 제거한 E2E 테스트에서 상태·제안이 출력된다. |

### 3.4 불확실성·UI·제어

| ID | 요구사항 | 수용 기준 |
|---|---|---|
| FR-UX-001 | 센서가 충돌하거나 신뢰도가 `conf_auto` 미만이면 자동 제어 대신 사용자 확인을 요청한다. | "졸음/리듬 타기/잘 모름" 중 2탭 이내로 응답하고, 결과가 원래 판정 참조와 함께 저장된다. |
| FR-UX-002 | Pi 5는 FSM 상태, 4단계 phase, 점수, 센서 유효성, 환경 값, 제안을 시각화한다. | hub 상태 발행 후 2초 이내에 화면이 갱신된다. |
| FR-UX-003 | 제안·경고는 Pi 5 내장 스피커로 짧은 알림을 선택적으로 출력한다. | 사용자가 소리를 끄고 켤 수 있고, 음성 원시 데이터를 수집하지 않는다. |
| FR-CTL-001 | 자동 제어는 신뢰도 게이트, 쿨다운, 실행 결과 확인을 거친다. | 동일 명령이 300초 내 재발행되지 않고 실패 시 사용자에게 표시된다. |

## 4. 비기능 요구사항

| ID | 항목 | 수용 기준 |
|---|---|---|
| NFR-PERF-001 | 성능 | Pi 4의 1회 FSM 판정은 500ms 이하. |
| NFR-REL-001 | 장애 격리 | 센서 1종·Node-RED·display 중단 시 hub가 생존하고 가용 신호만 재정규화. |
| NFR-REL-002 | 장시간 운영 | 버퍼 상한, 로그 rotation, systemd 재시작으로 8시간 연속 시연. |
| NFR-SEC-001 | 보안 | MQTT는 내부망 인증을 사용하고 자격증명을 저장소에 커밋하지 않음. |
| NFR-PRV-001 | 프라이버시 | 키 내용·카메라·상시 마이크·ToF raw의 운영 저장 금지. |
| NFR-MNT-001 | 변경성 | 임계값·가중치·타이머는 `hub/deskmate_hub/config/` YAML에서만 변경. |

## 5. MVP 종료 시나리오

1. ESP32의 ToF/mmWave/환경 특징과 PC 키 타이밍이 MQTT로 Pi 4에 도착한다.
2. Node-RED에서 최신 값·유효성·패킷 오류를 확인한다.
3. Pi 4가 baseline 후 PC/MIXED/NPC 맥락을 선택하고 피로 의심 상태를 발행한다.
4. ToF 숙임과 mmWave 모션 판정이 충돌하면 Pi 5가 졸음인지 리듬 타기인지 묻는다.
5. 사용자 응답이 Pi 4에 돌아오고 ESM 라벨로 로깅된다.
6. CO₂ 상승 또는 조도 부적합이 원인이면 환기/조명 제안이 나오고, 수락 후 제어 결과를 확인한다.

## 6. 보류 범위

- 피로·졸음에 대한 의료적 진단·안전 경고 장치 사용
- 학습 데이터 충분성 검증 전 TFLite/RL을 자동 제어의 단일 근거로 사용
- 개인화 opt-in·보존 기간·삭제 정책 확정 전의 장기 개인 로그 저장
