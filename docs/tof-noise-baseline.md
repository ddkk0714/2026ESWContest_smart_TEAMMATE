# ToF 잡음 기준선 — 벽만 보게 두고 "이 정도는 잡음" 정하기

기준일 2026-10-17 · 도구 `hub/atlas-tof/pc/noise_baseline.py` · 대상 VL53L8CX ×2 (장치 하나에 8×8 두 개)

자세 판정은 "기준 자세에서 얼마나 달라졌나" 를 본다. 그런데 센서는 가만히 있는 벽도 매 프레임 조금씩 다르게 잰다.
이 문서는 **장치를 벽 하나만 보게 고정하고 잰 흔들림을 기록해, 그보다 작은 변화는 잡음으로 치는 기준**을 만드는 절차다.
결과(JSON)는 세 곳에 쓴다.

1. **판정의 불감대** — zone 하나의 변화가 `noise_floor_mm` 보다 작으면 자세가 바뀐 증거로 쓰지 않는다.
2. **시뮬레이터 잡음 맞추기** — `dataset/tof_sim_v5` 의 `SensorModel.sigma_floor_mm`·`sigma_rel`·`dropout` 을 실측으로 바꾼다
   (지금 값은 그럴듯한 가정이고 `tools/fit_noise.py` 는 TODO 였다).
3. **하드웨어 회귀 검사** — 커버 유리·지그·펌웨어를 바꾼 뒤 같은 절차를 다시 돌려 숫자가 나빠지지 않았는지 본다.

## 언제 하나

- **지그(CAD 하우징)가 나온 뒤.** 지금(10-17)처럼 센서가 덜 고정된 상태의 값은 기준으로 쓰지 않는다.
  흔들리는 장착은 잡음이 아니라 장착 문제라 숫자가 부풀려진다.
- 하드웨어가 바뀔 때마다(커버 유리, 장착 각도, 펌웨어 측거 설정, 보드율) 다시.

## 준비

| 항목 | 기준 |
|---|---|
| 벽 | 평평하고 무광인 흰 벽(또는 큰 무광 보드). 유리·거울·창 금지 |
| 거리 | **센서 유리면에서 벽까지 축 방향 650 mm**(사람이 앉는 거리 중간값). 줄자로 두 번 잰다 |
| 각도 | 장치 정면이 벽에 수직. 지그 기본 각(위로 20°, 바깥 8°) 그대로 두면 벽이 비스듬해지므로 **이 측정만 장치를 세워 수직으로** 맞춘다 |
| 시야 | 45°×45° 안에 벽 말고 아무것도 없게. 650 mm 에서 시야 폭은 약 540 mm 다 — 책상 끝·모니터가 들어오지 않게 높이를 띄운다 |
| 조명 | 평소 실내등. 창이 있는 방이면 커튼을 친 것과 연 것 두 번 |
| 예열 | 측거 시작 뒤 2 분 기다린다(온도가 안정될 때까지 거리가 흐른다) |
| 경로 | ESP32 → Pi 4 UART → `uart_relay_board`(HTTP `:8772/raw`) 가 떠 있을 것. `docs/pi4-tofposture.md` |

## 절차

```bash
cd hub/atlas-tof/pc
# 1) 녹화 60 초 (센서당 5 Hz → 약 300 프레임)
python noise_baseline.py record --url http://<Pi4>:8772/raw --seconds 60 --out wall65_normal.jsonl
# 2) 분석
python noise_baseline.py analyze wall65_normal.jsonl --dist-mm 650 --note "흰 무광 벽, 실내등" --out noise_baseline_wall65_normal.json
```

조명을 바꿔 한 번 더(`wall65_window`). 시간이 되면 **450 mm·1000 mm** 도 같은 방법으로 잰다.
거리가 셋이면 "잡음이 거리에 따라 얼마나 커지나"(`sigma_rel`)를 맞출 수 있다. 650 mm 하나만으로는 바닥값(`sigma_floor_mm`)만 나온다.

녹화하는 동안 장치 앞을 지나가지 않는다. 지나갔으면 그 녹화는 버리고 다시 한다.

## 결과 읽기

센서마다 이렇게 나온다.

| 값 | 뜻 | 쓰는 곳 |
|---|---|---|
| `sigma_t_median_mm` / `p95` | zone 별 시간 표준편차의 중앙값 / 상위 5 % | 시뮬 `sigma_floor_mm` |
| `jump_p99_mm` | 이웃 프레임 사이 \|Δ\| 의 99 % | 순간 튐의 크기 |
| **`noise_floor_mm`** | `max(3·σ_t p95, |Δ| p99)` — **zone 하나가 이보다 덜 움직이면 잡음** | 판정 불감대 |
| `invalid_rate` | 상태값이 5·6·9·10 이 아닌 비율 | 시뮬 `dropout` |
| `bias_flat_median_mm` / `bias_radial_median_mm` | 벽까지 실제 거리 대비 평균 편차(축 거리 기준 / 광선 길이 기준) | 센서가 어느 거리를 보고하는지 판별 |
| `fixed_pattern_p95_mm` | zone 마다 늘 같은 방향으로 치우친 양 | 고정 오프셋 보정 필요 여부 |
| 8×8 σ 표 | zone 별 σ_t (row 0 = 위) | 가장자리·특정 zone 불량 찾기 |

두 편차 중 0 에 가까운 쪽이 센서가 보고하는 거리 정의다(평면 = 축 방향, 반경 = 광선 길이). 한 번 정하면 시뮬과 판정이 같은 정의를 쓰게 맞춘다.

## 합격 기준 (잠정, 첫 측정 뒤 고친다)

| 항목 | 기준 | 넘으면 |
|---|---|---|
| `invalid_rate` | 1 % 이하 | 커버 유리 오염·반사, 벽 재질 의심 |
| `sigma_t_p95_mm` @ 650 mm | 10 mm 이하 | 장착 흔들림, 예열 부족, 측거 설정 확인 |
| `fixed_pattern_p95_mm` | 15 mm 이하 | zone 별 오프셋 표를 만들어 빼 준다 |
| 두 센서 차이 | `noise_floor_mm` 이 서로 1.5 배 안 | 나쁜 쪽 센서·유리를 먼저 본다 |

## 기록

- 결과 JSON 은 레포에 넣지 않는다(장치마다 다르다). 노션 「센서 스펙」에 날짜·장치·조건과 위 표의 숫자만 옮긴다.
- 녹화 jsonl 은 사람이 안 찍힌 벽 거리뿐이라 개인정보는 없지만, 크기 때문에 레포 대신 팀 드라이브에 둔다.

## 2026-10-17 참고 측정 (기준 아님)

도구 확인용으로 고정 전 장치를 10 초 녹화했다(앞에 사람 없음, 벽 2.5~3.5 m + 60 cm 근처 물체).

- 60 cm 근처 물체 zone: σ_t 약 3 mm. 2.5~3.5 m 벽 zone: σ_t 10~40 mm. **잡음은 거리에 따라 커진다** — 650 mm 하나로 끝내지 말고 거리 셋을 재야 하는 이유다.
- 물체 가장자리 zone 은 가까운 것과 먼 것 사이를 오가며 \|Δ\| 가 1 m 넘게 튄다(혼합 픽셀). 벽 측정에서는 시야에 가장자리가 없게 해야 하고,
  판정의 불감대는 "가장자리 zone 은 따로 본다" 는 규칙이 필요할 수 있다.
- 무효 비율 18~34 % 는 먼 벽의 약한 신호 탓이다. 650 mm 벽에서는 훨씬 낮아야 정상이다.
