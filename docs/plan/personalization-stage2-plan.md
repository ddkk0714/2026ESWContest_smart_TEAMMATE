# 개인화 개발 계획: Pi 4 온디바이스 개인 head 학습

## 현재 목표와 개발 순서 (2026-10-08 수정)

사용자 결정: 제품 사용자가 데이터를 PC로 옮기거나 모델을 다시 설치할 필요 없이, Pi 4에서 개인 학습·평가·적용을 수행한다. 공통 모델 최초 학습·검증과 제품 빌드는 개발 PC에서 수행하며 운영 개인화는 클라우드·개발 PC 연결에 의존하지 않는다. PC 키스트로크 수집기는 작업 입력을 제공하는 별도 역할이다.

1. **온디바이스 학습 실행 기반 — 구현·PC 검증 완료, 보드 미검증.** 기존 공통 1D CNN backbone을 고정하고 마지막 16×4 softmax head만 학습한다. ATLAS native 확장에 의존하지 않는 순수 Python CNN·SGD 경로를 검증했다. 초기 공통 가중치는 Keras에서 portable JSON으로 변환하고 원본과 확률·embedding 출력을 비교한다. 기존 TFLite는 비교 경로로 유지한다. 실제 ATLAS에서 portable 또는 추후 native 경로를 선택하는 것은 실측 후 결정한다.
2. **동의 기반 특징·정정 연결 — 구현, 실기 미검증.** 승인된 정책의 동의가 있어야 사용한다. 보드 메모리에 제한된 embedding·ESM 정정만 모으며 수락/거절을 상태 정답으로 학습하지 않는다. 학습 표본은 현재 재부팅 시 사라진다. 디스크 표본 보존 기간·사용자별 분리는 팀 결정 후 별도 구현한다.
3. **유휴 학습·채택·복구 — 구현·PC 검증 완료, 보드 미검증.** IDLE·END에서 tick별 제한된 업데이트를 수행한다. 최소 train 2개·validation 1개·audit 1개 독립 세션과 각 분할의 클래스별 표본을 요구한다. validation/audit의 macro F1 개선·클래스별 recall 유지가 모두 충족돼야 채택한다. 감사 세션을 반복 사용해 재시도하지 않는다. 개인 head를 원자적으로 저장한 뒤 관찰 모델에 적용하며 손상·backbone 불일치 시 공통 head를 유지한다. 동의 철회는 학습 표본·후보·개인 head 사용을 중지하고 등록 파일을 삭제한다.
4. **Pi 4 IPK 실기 확인 — 남음.** 제한 Python 실제 실행, writable 경로·서비스 계정 권한, import·공통 추론·head 학습, p50/p95·메모리·발열·FSM tick 지연을 확인한다. 개발 PC 측정치를 보드 성능으로 보고하지 않는다. 소프트 budget은 한 업데이트 뒤 검사하며 평가·저장을 선점하지 않는다. 실측 후 별도 worker/native 최적화가 필요한지 결정한다.
5. **사용자가 이해할 수 있는 앱 상태 — 구현·위젯 검증 완료, 터치 실기 미검증.** 동의 화면에 기록 수집·학습·일시정지·개인 모델 준비 완료·기존 모델 유지·실패 상태를 표시한다. 연결 끊김·철회 시 오래된 개인 모델 상태를 숨기고 현재 관찰 전용임을 설명한다. PC 명령·파일 복사 없이 터치와 일상 사용으로 개인화가 진행되는지 실기에서 확인한다. 라벨 부족 시 공통 모델을 계속 사용한다.
6. **실사용자 평가 후 FSM 결합 — 남음.** 동의한 사용자의 독립 세션으로 실효성을 검증한다. 모델은 현재 observe 전용이며 자동 학습·채택도 FSM 상태·게이트·제어를 바꾸지 않는다. C_focus 부호·fusion은 팀 결정 및 회귀 후 연결한다.

완료 기준: PC 없이 사용하는 동안 개인 head가 보드에서 바뀌고, 독립 평가로 채택/거절되고, 재시작 복구·철회·삭제가 실제 기기에서 확인되어야 한다. 아래 PC 실험 완료 이력만으로 제품 온디바이스 개인화 완료로 표시하지 않는다.

설정·재현·한계: [온디바이스 개인화 구현](../ondevice-personalization.md).

첫 실기 검증 PR 범위와 인계는 [PR·실기 체크리스트](../ondevice-field-validation.md) 기준이다. 합성 입력의 서비스 시작 self-check를 추가했다. 현재 관찰 구현·UI·동의/삭제·회귀가 PR 범위이며 실제 Pi 4 실행·권한·속도와 Pi 5 터치 확인을 요청한다. FSM 결합과 실사용 효과까지 기다리지 않는다.

## 개발 순서와 완료 기준

1. **모델 계약과 hub 연결 기반** — 이번 개발 범위.
   - 기존 17개 특징 순서, 4개 클래스, 6 tick 창을 공유한다.
   - 관찰 모드에서 FSM 점수·상태·게이트·제어·리포트를 유지한다.
   - 비활성 기본값, 모델/metadata 누락·손상·불일치 및 추론 오류 폴백을 테스트한다.
   - 검증: 249 passed, 1 xfailed. 특징 일치·가짜 backend·제한 Python import·설정 패키징·회귀를 확인했다.
2. **PC 공통 모델 학습**.
   - 작은 1D CNN 후보부터 검토한다. 아키텍처 자체는 모델 계약에 고정하지 않는다.
   - 사용자/세션별 train/validation/test를 분리한다. 같은 세션의 겹친 창이 평가에 새지 않게 한다.
   - FSM 약한 라벨 일치율과 ESM 정정 라벨 성능을 나누어 보고한다. 합성 데이터 성능을 실제 집중도 정확도로 표현하지 않는다.
   - 완료 기준: 재현 명령·seed·출처·혼동행렬·macro F1·클래스별 recall·기준선 비교.
3. **backbone 동결 + 개인 head 재학습**.
   - 동의가 있는 PC 데이터만 사용하며 동의/저장 정책을 임의로 확대하지 않는다.
   - 별도 세션에서 공통 모델과 비교한다. 데이터 부족·편중·성능 악화 시 공통 모델을 유지한다.
   - 완료 기준: backbone 불변 확인, head 변화, 개인화 전후 비교 및 공통 모델 폴백.
4. **TFLite 변환과 PC 수치 검증**.
   - float32 입력 `[1,6,17]`, 확률 출력 `[1,4]`와 metadata를 만든다. 모델은 Git에 넣지 않는다.
   - 원본/변환 출력 오차와 top-1 일치를 검증하고 실제 모델 로딩·손상·shape/dtype 오류도 확인한다.
   - 완료 기준: 변환 재현 명령·모델 크기·latency·수치 오차 보고. ATLAS native 런타임 호환성은 보드에서 확인한다.
5. **관찰 비교 후 FSM 결합 설계**.
   - 같은 프레임 replay로 disagreement·저신뢰도·센서 누락을 평가한다.
   - `C_focus` 부호와 fusion 방식은 팀 결정 이후 구현한다. 모델 확률에 기존 행동 게이트를 바로 적용하지 않는다.
   - 완료 기준: 시간 조건·쿨다운·수락/거절/되돌리기·정정·리포트 회귀 및 모델 장애 시 FSM 유지.
6. **실센서 및 하드웨어 검증으로 복귀**.
   - 착석 → 집중 → 피로 → 제안 → 터치 수락 → 실제 제어 → MONITOR → 회복 → 리포트.
   - 수락·거절·무응답·되돌리기·정정, 센서 분리·브로커 재시작·화면 종료·인터넷 차단을 확인한다.
   - ToF 3분류·연결 경로, 스마트 플러그 모델, 자동 시작·UART 권한 복구, 하우징·발열·전원은 별도 실기 단계다.

## 가정과 남은 제한

- 후속 요청으로 공통 모델 학습과 개인 head 재학습까지 진행했다. 실제 사용자 효과는 미검증이며 TFLite 변환이 다음 단계다.
- 6 tick/17 특징은 기존 데이터 파이프라인을 따른다. 정규화 방식과 실제 tick 주기는 metadata와 hub 설정이 일치해야 한다.
- 기본 비활성이고 활성화해도 관찰 결과만 추가한다.
- 실모델·Pi 4 native 확장 호환성·성능·물리 제어는 미검증이다.
- 전체 저장소 자동 수집은 개발용 drop_test.py의 cv2 미설치로 실패했다. 명시적인 테스트 경로로 249개 통과를 확인했다.
