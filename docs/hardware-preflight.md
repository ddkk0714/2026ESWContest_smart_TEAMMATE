# 센서·FSM·Bluetooth 실기 전 점검

## 점검 범위와 제한

PC 키스트로크 집계값, mmWave 재실·체동·졸음 특징, 환경 센서 값을 실제 MQTT 계약으로
파싱하고 기본 FSM 설정으로 처리하는 자동 테스트를 추가했다. 센서 자체, UART 배선,
BLE GATT 서비스, A2DP 출력과 실제 조명 밝기·소리는 현장 확인이 필요하다.

현재 허브 센서 파서는 mmWave·환경·키스트로크를 지원한다. ToF 수집 경로는 아직
연결·결정되지 않았으므로 이 테스트가 ToF를 포함한 전 센서 통합 완료를 뜻하지 않는다.
호흡 점수는 기본 `respiration_enabled: false`이며 순간 심박을 피로 판단에 사용하지 않는다.

기존 예상 실패 테스트가 지적하는 결측 리스크는 남아 있다. 키스트로크·환경·경과시간 신호가
모두 미가용일 때 자세 신호만으로 점수가 재정규화되어 C_fatigue=1.0이 될 수 있다.
센서 연결·유효성을 먼저 확인하고 이 결측 상황을 정상적인 피로 판정 성공으로 기록하지 않는다.

## 수정한 실행 경로

1. 피로 의심이나 미수락 제안에서 조명·음악을 먼저 실행하지 않는다.
2. 제안 대기 중에는 개발용 `auto_complete_actions`로 다음 10초 tick에 완료 처리하지 않는다.
   대기 중 게이트는 suggest로 유지하며 수락·거절·만료까지 원인을 보존한다.
3. 같은 국면에서 조명 쓰기가 실패하면 재시도한다. BLE 프레임은 직렬화하고 성공한 국면만 기억한다.
   램프 연결에 실패한 일체형을 전체 성공으로 안내하지 않으며 재연결 성공 뒤 실패 표시를 해제한다.
4. 허브의 desk_lamp 명령을 앱이 구독해 실행하고 결과를 응답한다. 중복 명령은 다시 쓰지 않는다.
5. 제안 명령의 실행 유효 시간은 수락 후 발행 때부터 계산한다. 앱도 큐 대기·연결 후 만료를 확인한다.

환경 개입의 운영 경로는 아래와 같다.

```text
센서 MQTT/UART → SensorCache → SensorFrame → FSM ACTION_ENV
  → interaction/request → 앱 수락 → feedback/user
  → 허브 control/cmd → 앱 iLink GATT 쓰기 → control/result → MONITOR
```

인지성·자세성 제안은 앱의 수락 뒤 로컬 조명·음악 피드백을 적용한다.
`ACTION_BREAK` 수락은 REST로 진행한다. 거절·무응답은 제어하지 않고 MONITOR로 진행한다.

## 기본 설정에서 기다려야 하는 시간

`hub/deskmate_hub/config/fsm.yaml`은 다음 값을 유지한다.

- 계산 주기: 10초.
- 시작 기준선 측정: 300초.
- 피로 상승 유지: 180초, 피로 확정 유지: 추가 180초.
- 피로 확정 기준: C_fatigue 0.70 이상.
- 제안 게이트: 0.45 이상 0.75 미만. 0.75 이상은 자동 개입으로 제안 카드가 없을 수 있다.
- 제안 응답 시간: 180초. 휴식 최소 시간: 300초.
- 환경 제어 결과 대기: 발행 후 15초. 동일 대상·동작 쿨다운: 300초.

한 번 센서 값을 바꿨다고 즉시 피로 확정·카드 표시가 되는 구조가 아니다.
임계값을 낮춰 실측 성공처럼 기록하지 말고, 짧은 리허설에는 기존 demo 프로파일을 별도로 사용한다.

## 현장 순서와 통과 기준

1. **연결**: Pi 4 브로커·허브 기동, Pi 5의 MQTT 주소·포트 확인, PC·Pi 시계 동기화.
   앱의 개발자 상태 고정을 해제하고 내장 데모 표시가 아닌지 확인한다.
2. **개별 입력**: PC에서 `python -m collector --broker <Pi4-IP> --port 1883` 실행.
   키스트로크 탭의 1Hz 표본 갱신, mmWave 재실·체동 변화, 환경값·유효성 표시를 각각 확인한다.
   입력을 멈추면 typing_active=false, 수집기를 종료하면 5초 초과 후 수신 끊김이어야 한다.
3. **출력 분리 검사**: Bluetooth에서 BLE 램프와 A2DP 스피커를 각각 연결한다.
   조명 25%와 100% 테스트를 눌러 밝기 차이를 확인하고 음악 테스트와 볼륨을 확인한다.
   이미 연결된 스피커를 다시 선택하거나 저장 주소로 재연결해도 실패 표시 없이 Bluetooth 출력이 선택돼야 한다.
   이 단계가 실패하면 FSM과 별도로 권한·GATT 특성·A2DP 활성 출력·기기 전원을 점검한다.
4. **FSM 경로**: 자동 피드백 스위치를 켠 뒤 정상 입력으로 기준선을 만들고 특징 변화를 유지한다.
   FOCUS → FATIGUE_SUSPECT → FATIGUE → CAUSE_ANALYSIS → ACTION_*를 확인한다.
5. **수락**: 제안 게이트에서 최소 30초 기다린 뒤 수락한다. 대기 중 조명·음악이 실행되지 않아야 한다.
   환경 개입이면 feedback/user → control/cmd → control/result의 동일 command_id를 확인한다.
   밝기 값은 iLink 원시 0~255다. 기본 환경 명령 70은 약 27%이고 70%가 아니다.
6. **거절·만료·회복**: 다른 제안에서 거절하거나 180초 기다린다. 실행 없이 종료되어야 한다.
   휴식 수락은 REST, 300초 뒤 RECOVERY를 확인한다. 자동 조명 명령의 되돌리기도 별도 확인한다.

현재 기본 환경 개입에는 vent_fan도 포함된다. 실제 팬 어댑터가 없으면 팬 명령은 15초 뒤
timeout이 되는 것이 정상이며, 앱은 팬 성공을 대신 응답하지 않는다. mock 어댑터를 같이
실행하면 실제 조명 쓰기 실패를 모의 성공이 가릴 수 있으므로 운영 검증과 분리한다.
기존 PC iLink phase 컨트롤러도 앱과 같은 램프에 동시에 실행하지 않는다.

`control/result.succeeded`는 GATT 쓰기 완료다. 실제 밝기 변화와 실제 소리는 직접 확인해 기록한다.
실기 성공 기록에는 브랜치·커밋/수정본, 사용 설정, 대상 장비, 센서 변화, 상태 순서,
요청·명령 ID와 결과, 육안·청각 확인 결과를 함께 남긴다. 키 내용·개인 입력 로그는 기록하지 않는다.

## 자동 검증 명령

```bash
python -m pytest hub/tests collector/tests -q
cd display/atlas/ui_env_app
flutter test --no-pub --reporter expanded
flutter analyze --no-pub --no-fatal-infos
```

Headless 테스트에서 pynput은 `PYNPUT_BACKEND=dummy`로 실행한다. 실제 입력 후킹을 시작하지 않는다.
`hub/tests/test_sensor_feedback_flow.py`는 기본 기준선·가중치·타이머로 센서 변화, 제안 대기,
수락/거절/만료와 휴식 후 회복을 검증한다. 앱 테스트는 소켓 MQTT 명령·결과와 가짜 BLE
쓰기를 검증하며 실기 BLE 확인을 대체하지 않는다.
