# 하드웨어 구성 · BOM

## 구성

| 계층 | 장치 | 역할 |
|---|---|---|
| 센싱 | ESP32 × N | mmWave·환경 센서 말단 노드. 1차 전처리 후 UART/MQTT 후보 경로로 Pi 4 전달 |
| 추론 | Raspberry Pi 4 | 중앙 허브. 통신 broker/adapter 후보 + 특징 융합 + FSM/TFLite 추론 + 제어 판단 |
| 출력 | Raspberry Pi 5 (8GB) | AI Native OS Video Profile 디스플레이 단말. Atlas Flutter 상태·제안·리포트·피드백 UI |
| 학습 | PC | 모델 학습 → TFLite 변환 → Pi 4 배포. 키스트로크 수집기도 여기서 구동 |

> **3종 HW 유지 필수.** Pi 5 가 강력해도 Pi 4 의 허브 역할을 Pi 5 로 합치지 않는다.
> ESP32 · Pi 4 · Pi 5 3종 연동이 "3종 HW 연동 AI 가전" 가산점 요건이다.
> LG 기술교육 제공 구성은 Pi 5의 AI Native OS Video Profile, Pi 4B의 Headless Profile, ESP32이며 AI Native OS 사용은 필수다.

## 센서

| 센서 | 부품 | 인터페이스 | 용도 |
|---|---|---|---|
| ToF 54×42 | VL53L9CX | Pi 4 MIPI CSI-2 우선 검증, 실패 시 ESP32 I2C 축소 | 재실·자세·모션·노딩 |
| ToF 시험용 | VL53L0X | Pi 5 I2C `0x29` | 연결·I2C bring-up 전용, 제품 센서 아님 |
| mmWave | SEN0623 (C1001) | UART, 115200bps | 재실 · 정지/활동 · 호흡/심박 보조, ToF 교차 검증 |
| CO₂ · 온습도 | SEN0536 (SCD41) | I2C `0x62` | 환경 맥락 · 환기 트리거 |
| 조도 | SZH-EK070 (BH1750 GY-302) | I2C | 조명 제어 · 환경 맥락 |
| 공기질 | ENS160 | I2C | (선택) 환경 맥락 |
| I2C 멀티플렉서 | TCA9548A | — | I2C 경로에서 동일 주소 센서가 2개 이상일 때 검토 |

VL53L9CX의 실제 호스트 인터페이스·드라이버·처리율은 1일 연결 spike에서 확정한다. 정상 운영은 특징값만 사용하고 축소 depth map은 디버그/UI 모드에서 최대 2Hz로 제한한다.

### 추가 선발주 권장

- SCD41 (CO₂) — 환기 제어 데모의 핵심
- BH1750 (조도)
- SEN0623 (C1001 mmWave) — ToF 자세·노딩 판정의 교차 검증
- Pi 5 27W PSU · 액티브 쿨러 (지원 장비에 없을 경우)
- 스마트 플러그 + LED 스탠드 / 환기팬 — **기본 제어 데모 라인**

## 제어 데모 라인

ThinQ 실기기 연동은 LAN · 플랫폼 접근 · NDA · 부스 물류 부담이 크다.
스마트 플러그 + LED 스탠드 / 환기팬을 **기본 제어 라인**으로 먼저 완성하고,
실제 ThinQ 연동은 **1개 기기만** 시연한다.
